# 定位

本场景用于存量重建，不是增量修补。重建意味着新产物从空开始生成，不是把旧文档拿来修订。

本 skill 不新增代理，执行复用既有 `ddd-*` 代理。触发时机由人工判断，落在入口：模型不得在常规迭代中提议并执行重建，本 skill 也不被自动选中，只由用户以 `/skill:ddd-rebuild` 显式调用。

# 前置检查

1. 确认版本控制系统在场且可用。
2. 确认工作区无未提交改动，或已有明确的处置记录。
3. 记录回溯点标识，含提交哈希、分支名与记录时间，可按需附加标记。
4. 把回溯点标识写入重建产物并持久化。

任一步骤不通过即停止并报告，不得动工。丢弃是相对旧版本的丢弃，不是绝对丢失。旧版本始终可回溯，需要参照旧实现时从回溯点读取，不在案保留旧文件。

# 流程

| 序 | 阶段 | 执行者 | 产出 | 门 |
|---|---|---|---|---|
| 1 | 前置检查与回溯点 | 根会话 | 回溯点记录 | 前置检查门 |
| 2 | 现状全量盘点 | scout | 现状盘点与锚点候选 | 无 |
| 3 | 锚点冻结 | 根会话与用户 | 冻结锚点清单 | 锚点冻结门 |
| 4 | 新设计生成 | ddd-architect 与 ddd-decomposer | 架构与设计文档树 | 接口评审门 |
| 5 | 实施 | ddd-implementer | 代码与测试 | 无 |
| 6 | 集成收口 | ddd-fixer | 集成收口结论 | 无 |
| 7 | 验证 | ddd-tester | AC 全量回归报告 | 重建验收门 |
| 8 | 审计 | ddd-auditor | 审计报告 | 审计门 |
| 9 | 废弃清除 | ddd-fixer | 废弃清单与清除记录 | 无 |
| 10 | 基线重写 | 根会话 | 架构基线 | 无 |

第 2 步属发散段，产物为草稿，不入基线；第 3 步为冻结门；第 4 步起属收敛段，不得夹带范围外变更，第 2 步的草稿在冻结后作废，只有冻结后的产物进入正式文档树。

第 4 步须整篇重写而非修订旧文档；第 7 步的等价性以 AC 全量回归验证，不得以子集用例证明等价。

# 锚点冻结门

第 3 步为唯一的人工作用门，冻结前不得进入第 4 步。用户未确认锚点即不得进入收敛段。

冻结后不得扩范围，锚点之外一律可弃。草稿在冻结后作废。

# 开放与约束

| 开放 | 绝对约束 |
|---|---|
| 架构方案、目录划分、技术选型、实现路径、拆分粒度、内部命名 | 产物形态与字段、流程顺序与门禁、锚点继承、废弃声明、等价性验证、回溯点记录、变更记录 |

开放区的含义是重构者可自由选择最优形态，不受旧实现的任何结构牵制。约束区的含义是无论方案如何选，产物与流程都必须按本 skill 与规范「存量重建」节的契约产出，不得自创格式或跳过门禁。

# 停止条件

前置检查不通过、用户未确认锚点、AC 全量回归未通过、审计有阻断项时，停止并报告，不得继续后续步骤。
