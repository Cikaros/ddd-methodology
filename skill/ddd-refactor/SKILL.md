# 定位

本场景用于定向重构，范围限于用户指定的模块或问题，不做范围外改动。它是存量重建的局部特例，除范围限定外，防堆叠约束同等适用。

本 skill 不新增代理，执行复用既有 `ddd-*` 代理。触发时机由人工判断，落在入口：模型不得在常规迭代中提议并执行重构，本 skill 也不被自动选中，只由用户以 `/skill:ddd-refactor` 显式调用。

# 前置检查

1. 确认待重构范围可被明确描述，即用户指出具体模块或问题。
2. 确认版本控制系统在场，并记录回溯点。

任一步骤不通过即停止并报告，不得动工。

# 流程

| 序 | 阶段 | 执行者 | 产出 | 门 |
|---|---|---|---|---|
| 1 | 问题界定与影响面圈定 | scout | 问题界定与受影响接缝 | 无 |
| 2 | 范围与锚点确认 | 根会话与用户 | 冻结范围与锚点 | 锚点冻结门 |
| 3 | 设计修订 | ddd-decomposer，涉及架构时加 ddd-architect | 设计文档修订 | 接口评审门，仅当接口变化时 |
| 4 | 实施 | ddd-implementer | 代码与测试 | 无 |
| 5 | 集成收口 | ddd-fixer | 集成收口结论 | 无 |
| 6 | 验证 | ddd-tester | 回归报告 | 无 |
| 7 | 审计 | ddd-auditor | 审计报告 | 审计门 |

第 1 步属发散段，产物为草稿，不入基线；第 2 步为冻结门；第 3 步起属收敛段，不得夹带范围外变更。

# 锚点冻结门

第 2 步为唯一的人工作用门，冻结前不得进入第 3 步。用户未确认范围即不得进入收敛段。

冻结后不得扩范围，锚点之外一律可弃。草稿在冻结后作废。

# 开放与约束

| 开放 | 绝对约束 |
|---|---|
| 架构方案、目录划分、技术选型、实现路径、拆分粒度、内部命名 | 产物形态与字段、流程顺序与门禁、锚点继承、废弃声明、等价性验证、回溯点记录、变更记录 |

开放区的含义是重构者可自由选择最优形态，不受旧实现的任何结构牵制。约束区的含义是无论方案如何选，产物与流程都必须按本 skill 与规范「存量重建」节的契约产出，不得自创格式或跳过门禁。

## 防堆叠约束

这是定向重构与普通增量改造的关键区别，三条同等适用。

1. 范围外文件不得改动，发现问题即登记为存量债务，不在本轮顺带处理。
2. 被重构范围内的产物整篇重写，不得在旧文本上追加。
3. 完成后须给出本次范围内的废弃项清单，即使为空也须显式声明为空。

# 产物

本轮产出三件，逐项按 `~/.pi/agent/skills/ddd-methodology/references/templates-rebuild.md` 的对应模板生成，范围节填写本次的模块或问题。

| 产物 | 模板节 |
|---|---|
| 冻结范围与锚点清单 | ANCHORS 冻结锚点清单 |
| 范围废弃项清单 | DEPRECATED 废弃清单 |
| 回归报告 | REBUILD_VERIFY 重建验证报告 |

回归报告的 AC 全量回归一节改为本轮范围内的受影响 AC 加与其相关的外部 AC。

# 停止条件

前置检查不通过、用户未确认范围、AC 全量回归未通过、审计有阻断项时，停止并报告，不得继续后续步骤。
