# 注释与文件纪律知识切片

## 注释纪律
1. 注释只解释"为什么"，即意图、坑位依据、约束来源；不复述代码做了什么。
2. 注释只描述当前代码，不牵连过程：禁止修复史与对比叙述、轮次与编号、改动者与时间；读者只读当前代码与注释即可理解现状，过程信息属 git 历史与 issues。
3. 禁止逐行注释、大段叙述、与代码重复的 docstring；自解释实现不加注释。
4. 改代码时同步修订注释，过时注释必须删除。

## 文件级注释
每个源码文件头部的说明注释应说明该文件的目标与范围：文件存在目的、承载的能力边界、不包含什么；随文件粒度拆解同步维护。

## 替换优先于追加
改动落笔前先判断：应再补一条，还是应把既有表述重写为准确的当前描述。累积追加必须替换、合并或删除：
- 注释块出现多条历史式补充 → 重写为一段当前约束说明；
- 并列的字段与方法（同义不同名或同名不同义）→ 合并；
- 文件持续膨胀而职责相近 → 拆分或合并，不许只增不减；
- 同一函数被反复打补丁 → 重构，而非继续叠加守卫。
该原则适用于字段、方法、类与文件，不限注释。

## 单一权威与声明可验证

1. 同一规则不得多处并列定义，其余位置只留指针。
2. 任何声明必须有消费方与验证手段；无消费方的声明不得引入，已存在的一律修剪。
