## 12. 声明面可验证与修剪

**铁律：不被消费的声明是危险的，因为无人验证其正确性。**

- [ ] 每条声明同时具备消费方与验证手段，缺一不得引入。

声明面包括接口契约、公开导出、能力清单、规则条款、配置项、模板字段与依赖项。本条的执行入口为 G6，即审计报告未过则不得交付。

审计类代理必须全量核对，不得因看似无用、低风险或成本高而跳过；对每项回答是否被消费与消费是否正确；发现无消费方声明即报缺陷，不得静默留存；声明面审计的反向抽查不少于三项并实测消费路径真的通，专项审计可自行提高下限。

**探索性审计。** 审计除按清单逐项核对与反向抽查外，须显式记录清单之外的检索面与结论，作为清单核对之外的第二条记录。判据两条：有发现时登记其归属，即归入逐项审计表或修剪清单；无发现时说明已检索的范围与所用手段，使无发现成为可复核的结论而非缺省。不得以「清单全通过」代替本项记录，也不得为填满本项而虚构发现；本项以检索面与结论齐备为通过条件，不以发现数量为通过条件。

审计必须同时核验**变更记录当轮声称与实际产物是否相符**，声称与实际不符即为缺陷，与代码缺陷同级处理。

无用代码与冗余声明必须删除，不得注释保留，不得以将来可能用到为由滞留。**写入者的清理义务范围限于所触及文件内的连续注释代码与兼容层标记，即文件级属性；无引用文件属仓库级属性，由审计代理处理，不入写入义务。**删除前确认无消费方并登记变更记录。义务的完整性见「结构与契约的演进治理」节的触碰即治理。

写入者的清理义务触发点：结构健康度量显示恶化时、G6 交付前、需求变更后、能力新增后、版本收尾、重建完成后。

审计报告由审计代理在标题下方给出建议归档名，格式为 G6-序号-版本，**序号取 docs/audits/ 现存最大序号加一，被删归档不占序号，目录不存在时从 001 起**；审计代理为只读，**落盘由根会话执行**，写入 `<项目根>/docs/audits/`。**修剪清单在下次审计时必须逐项回验是否真的删除**，回验输入取自该目录内上一份报告。

pi 运行时契约类声明，如 worktree、control 字段与 frontmatter 字段，以冒烟检查与运行时观察为验证手段，不因无法离线验证而判为纸面消费方。

### 12.1 存量债务的登记与清偿

存量债务指承接方判定为范围外、或须先补设计预判因而未在本轮清偿的项。登记不是免责，而是清偿的入口：只写出口即登记而不写入口即清偿，解耦即退化为无出口的累积。下列五件机制构成最小闭环。

**统一登记簿与其字段**。登记簿为 `<项目根>/docs/debts.json`，是存量债务的唯一登记处，替代散落在变更记录句子、设计文档范围节与审计报告三处的登记。顶层三字段固定：`currentVersion` 记录当前版本，`maxOpen` 记录未清上限，`defaultDueSpan` 记录默认时限跨度；另有条目数组字段 `debts`，其元素字段固定如下。

| 字段 | 含义 |
|---|---|
| id | 编号，形如 D-001，仓库内唯一 |
| desc | 一句话描述 |
| registeredAt | 登记时的版本 |
| owner | 承接方，须具名，即具体代理名或根会话 |
| dueBy | 应清版本，可省；省略时由校验脚本按登记版本加 `defaultDueSpan` 推导 |
| status | open 或 closed |
| reason | 登记理由，例如范围外、需先补设计预判 |
| rootCause | 根因分类，取五类之一：声明与事实脱节、单一权威被违背、机械校验有盲区、规则演进后消费方未同步、反复修补同一处 |
| recurrence | 复发记录，含 count 与 lastVersion；count 为非负整数，lastVersion 在 count 为零时为 null，否则形如 v主.次 |

**具名承接**。owner 必填且具名，禁止「留待下一轮」这类无对象的表述，因其无承接方，等于无人负责。

**清偿时限**。登记时给出应清版本 `dueBy`，亦可省略；省略时由校验脚本按登记版本 `registeredAt` 加 `defaultDueSpan` 推导应清版本，其默认为二，即登记版本加二，两版本内清偿。该跨度与本方法论既有的两轮语义同源，不引入新的阈值体系。债务的版本跨度与缺陷的修复轮次是两个不同的量，前者按登记版本与应清版本计，后者按同一缺陷的轮回计，不得混读。

**超期校验与升级**。超期校验由机械校验承担，读登记簿与当前版本，逐项判定未清项是否超期；超期即阻断。连续两轮超期则强制升级用户。这是把既有的两轮升级语义从缺陷扩展到债务，该语义见「缺陷四级路由」节。同一根因分类连续两版登记为未清，即判该根因未被真正处理，须在下一轮升级用户并登记为结构性问题，与超期的两轮升级语义同源。

**总量上限**。未清项总数上限为 `maxOpen`，为固定默认值十项；「约三倍」仅说明该默认值的由来，不构成计算规则或校验公式，校验一律以字面值为准。超限即触发专项清偿轮，该轮不得新增功能。

关系说明（不计入机制数）：债务不是缺陷，缺陷走「缺陷四级路由」节的定级路由，而债务是范围外或待补预判的项，登记后仍须按期清偿，二者共用两轮升级语义而以登记簿区分承接形态。改造影响评估的存量债务承接列是债务的入口来源之一，其承接方即登记簿的 owner。登记簿的时效由「结构与注释的机械证据」节的脚本消费契约表所列 `debt-check.js` 判定，其超期结论作交付门前置校验。

## 13. 结构与注释的机械证据

`node ~/.pi/agent/skills/ddd-methodology/scripts/code-health.js <项目根>` 输出五类事实，作为 G5-INT 的证据源与 G6 审计的输入。度量写入 `<项目根>/docs/health.json`，**该文件入版本管理作为趋势证据，历史上限 50 条**，超出由脚本截断。输出含 `[告警]` 段，列出扫描面内不可读的目录与文件，无不可读条目时输出 `[告警] 无`；该段与末行结论同为固定行，输出超限截断明细时保留。

| 类别 | 覆盖的事实 | 机械程度 |
|---|---|---|
| 文件规模 | 超 500 行的代码文件、基础或核心模块文件超 300 行、活文档与设计文档超 200 行、设计文档契约数超 10 项、各类接近上限文件 | 完全 |
| 死代码 | 连续注释代码块、兼容层标记、无引用文件 | 大致，不可达分支需 AST 故未覆盖 |
| 重复嫌疑 | 同名声明跳文件出现 | 弱信号，语义级重复需审计代理判定 |
| 注释 | 违禁模式与提及已不存在标识符的过时引用 | 部分，是否解释为什么不可机械判定，由审计代理抽检 |
| 结构趋势 | 被触碰文件的规模变化，超阈值文件数相对上轮的增减 | 完全 |

度量落盘的文档规模与契约数字段：`docFiles` 为纳入度量的文档份数，即活文档加设计树内设计文档，`docOversized` 为行数超文档阈值的文档数，`docNearLimit` 为行数接近文档阈值的文档数，`designFiles` 为纳入度量的设计文档份数，`contractOversized` 为契约数超上限的设计文档数，`contractNearLimit` 为契约数接近上限的设计文档数；文档规模与契约数超限、接近上限仅报告不阻断，其阈值与承载体见「机械约束」节。契约数的计数口径唯一权威在本节：取设计文档「对外接口与约定」节的表格数据行数，表头与分隔行不计，该节无表格时取列表项数，接近上限为上限的零点八倍。

默认：上表未列出的结构事实不由 `code-health.js` 输出，须由审计代理语义判定；活文档规模已列入上表文件规模类，由 `code-health.js` 度量。

度量仅报告不阻断，其阻断地位由 G5-INT 的治理条件承接。度量恶化的具体项写入审计报告的必填节。

| 脚本 | 输出形态 | 机读结论 | 退出码 | 门禁地位 | 输出上限 |
|---|---|---|---|---|---|
