本文件承载「声明面可验证与修剪」与「结构与注释的机械证据」两节；不包含门禁路由、变更与改造条款。

## 12. 声明面可验证与修剪

**铁律：不被消费的声明是危险的，因为无人验证其正确性。**

- [ ] 每条声明同时具备消费方与验证手段，缺一不得引入。

声明面包括接口契约、公开导出、能力清单、规则条款、配置项、模板字段与依赖项。本条的执行入口为 G6，即审计报告未过则不得交付。

审计类代理必须全量核对，不得因看似无用、低风险或成本高而跳过；对每项回答是否被消费与消费是否正确；发现无消费方声明即报缺陷，不得静默留存；声明面审计的反向抽查不少于三项并实测消费路径真的通，专项审计可自行提高下限。

**探索性审计。** 审计除按清单逐项核对与反向抽查外，须显式记录清单之外的检索面与结论，作为清单核对之外的第二条记录。判据两条：有发现时登记其归属，即归入逐项审计表或修剪清单；无发现时说明已检索的范围与所用手段，使无发现成为可复核的结论而非缺省。不得以「清单全通过」代替本项记录，也不得为填满本项而虚构发现；本项以检索面与结论齐备为通过条件，不以发现数量为通过条件。

审计必须同时核验**变更记录当轮声称与实际产物是否相符**，声称与实际不符即为缺陷，与代码缺陷同级处理。

无用代码与冗余声明必须删除，不得注释保留，不得以将来可能用到为由滞留。**写入者的清理义务范围限于所触及文件内的连续注释代码与兼容层标记，即文件级属性；无引用文件属仓库级属性，由审计代理处理，不入写入义务。**删除前确认无消费方并登记变更记录。义务的完整性见「结构与契约的演进治理」节的触碰即治理。

写入者的清理义务触发点：结构健康度量显示恶化时、G6 交付前、需求变更后、能力新增后、版本收尾、重建完成后。

审计报告由审计代理在标题下方给出建议归档名，格式为 G6-序号-版本，**序号取 docs/audits/ 现存最大序号加一，被删归档不占序号，目录不存在时从 001 起**；审计代理为只读，**落盘由根会话执行**，写入 `<项目根>/docs/audits/`。**修剪清单在下次审计时必须逐项回验是否真的删除**，回验输入取自该目录内上一份报告。

pi 运行时契约类声明，如 worktree、control 字段与 frontmatter 字段，以冒烟检查与运行时观察为验证手段，不因无法离线验证而判为纸面消费方。

### 12.1 存量债务的登记与清偿

存量债务指承接方判定为范围外、或须先补设计预判因而未在本轮清偿的项。登记不是免责，而是清偿的入口：只写出口即登记而不写入口即清偿，解耦即退化为无出口的累积。下列五件机制构成最小闭环。

**统一登记簿与其字段**。登记簿为 `<项目根>/docs/debts.json`，是存量债务的唯一登记处，替代散落在变更记录句子、设计文档范围节与审计报告三处的登记。顶层三字段固定：`currentVersion` 记录当前版本，`maxOpen` 记录未清上限，`defaultDueSpan` 记录默认时限跨度；另有条目数组字段 `debts`，其元素字段固定如下。

| 字段 | 含义 |
|---|---|
| id | 编号，形如 D-001，仓库内唯一 |
| desc | 一句话描述 |
| registeredAt | 登记时的版本 |
| owner | 承接方，须具名，即具体代理名或根会话 |
| dueBy | 应清版本，可省；省略时由校验脚本按登记版本加 `defaultDueSpan` 推导 |
| status | open 或 closed |
| reason | 登记理由，例如范围外、需先补设计预判 |
| rootCause | 根因分类，取五类之一：声明与事实脱节、单一权威被违背、机械校验有盲区、规则演进后消费方未同步、反复修补同一处 |
| recurrence | 复发记录，含 count 与 lastVersion；count 为非负整数，lastVersion 在 count 为零时为 null，否则形如 v主.次 |

**具名承接**。owner 必填且具名，禁止「留待下一轮」这类无对象的表述，因其无承接方，等于无人负责。

**清偿时限**。登记时给出应清版本 `dueBy`，亦可省略；省略时由校验脚本按登记版本 `registeredAt` 加 `defaultDueSpan` 推导应清版本，其默认为二，即登记版本加二，两版本内清偿。该跨度与本方法论既有的两轮语义同源，不引入新的阈值体系。债务的版本跨度与缺陷的修复轮次是两个不同的量，前者按登记版本与应清版本计，后者按同一缺陷的轮回计，不得混读。

**超期校验与升级**。超期校验由机械校验承担，读登记簿与当前版本，逐项判定未清项是否超期；超期即阻断。连续两轮超期则强制升级用户。这是把既有的两轮升级语义从缺陷扩展到债务，该语义见「缺陷四级路由」节。同一根因分类连续两版登记为未清，即判该根因未被真正处理，须在下一轮升级用户并登记为结构性问题，与超期的两轮升级语义同源。

**总量上限**。未清项总数上限为 `maxOpen`，为固定默认值十项；「约三倍」仅说明该默认值的由来，不构成计算规则或校验公式，校验一律以字面值为准。超限即触发专项清偿轮，该轮不得新增功能。

**债务历史快照与根因复发检测**。`debt-check.js` 每次运行时维护 `<项目根>/docs/debt-history.json`，其 `history` 数组按版本新增或就地更新，同一版本重复运行不产生重复条目；每条快照含记录时间 `at`、版本 `version` 与当时全部条目摘要，摘要字段为编号 `id`、根因分类 `rootCause`、状态 `status`、登记版本 `registeredAt` 与应清版本 `dueBy` 五项；历史上限五十条，超出截断，与健康度量产物同口径。复发判定为机械口径：某根因分类在上一版本快照中已有未清项，且当前版本新增登记的债务中含同根因条目，即判该根因复发；`debt-check.js` 以独立段落列出复发的根因分类、牵涉条目与涉及版本，该段落不改变其末行结论与退出码语义。复发后的升级由根会话与审计代理承接，与连续两轮超期交由人工裁决一致。复发计数的更新责任在根会话：登记同根因的新债务时，对既有同根因条目递增 `recurrence.count` 并记最近复发版本 `recurrence.lastVersion`。

**教训回写**。清偿根因为「机械校验有盲区」的债务时，该根因须转化为新的机械校验项，不得只改文档。触发条件为债务的根因分类是「机械校验有盲区」且清偿方式为新增或扩展机械校验；执行者为根会话；产出物为 `<项目根>/docs/check-coverage.json`，其中逐条登记根因分类到已建立校验项的映射，条目另给出所引来源债务编号；脚本类校验项以脚本文件名标识、仓库内校验项以校验编号标识。判据为映射中的每个校验项真实存在且被机械校验消费，即脚本文件存在于 `scripts/` 或校验编号属于 `ref-check.js` 的校验清单；条目的来源债务编号在登记簿中存在且状态为已清偿；条目的根因分类与该债务登记的根因分类一致。上述三项由机械校验逐条核对，任一不成立即判漂移；不得为凑数登记不存在的虚项。**反向完整性**：以新增或扩展机械校验清偿且根因为「机械校验有盲区」的债务，须在映射中有对应条目；该完整性无机械判据，由审计代理核验，机械校验只做上述存在性与一致性三项。

关系说明（不计入机制数）：债务不是缺陷，缺陷走「缺陷四级路由」节的定级路由，而债务是范围外或待补预判的项，登记后仍须按期清偿，二者共用两轮升级语义而以登记簿区分承接形态。改造影响评估的存量债务承接列是债务的入口来源之一，其承接方即登记簿的 owner。登记簿的时效由「结构与注释的机械证据」节的脚本消费契约表所列 `debt-check.js` 判定，其超期结论作交付门前置校验。

## 13. 结构与注释的机械证据

`ddd_code_health` 工具（`root` 传被开发项目根的绝对路径）输出五类事实，作为 G5-INT 的证据源与 G6 审计的输入。度量写入 `<项目根>/docs/health.json`，**该文件入版本管理作为趋势证据，历史上限 50 条**，超出由脚本截断。输出含 `[告警]` 段，列出扫描面内不可读的目录与文件，无不可读条目时输出 `[告警] 无`；该段与末行结论同为固定行，输出超限截断明细时保留。

| 类别 | 覆盖的事实 | 机械程度 |
|---|---|---|
| 文件规模 | 超 500 行的代码文件、基础或核心模块文件超 300 行、活文档与设计文档超 200 行、设计文档契约数超 10 项、各类接近上限文件 | 完全 |
| 死代码 | 连续注释代码块、兼容层标记、无引用文件 | 大致，不可达分支需 AST 故未覆盖 |
| 重复嫌疑 | 同名声明跳文件出现 | 弱信号，语义级重复需审计代理判定 |
| 注释 | 违禁模式与提及已不存在标识符的过时引用 | 部分，是否解释为什么不可机械判定，由审计代理抽检 |
| 结构趋势 | 被触碰文件的规模变化，超阈值文件数相对上轮的增减 | 完全 |

度量落盘的文档规模与契约数字段：`docFiles` 为纳入度量的文档份数，即活文档加设计树内设计文档，`docOversized` 为行数超文档阈值的文档数，`docNearLimit` 为行数接近文档阈值的文档数，`designFiles` 为纳入度量的设计文档份数，`contractOversized` 为契约数超上限的设计文档数，`contractNearLimit` 为契约数接近上限的设计文档数；文档规模与契约数超限、接近上限仅报告不阻断，其阈值与承载体见「机械约束」节。契约数的计数口径唯一权威在本节：取设计文档「对外接口与约定」节的表格数据行数，表头与分隔行不计，该节无表格时取列表项数，接近上限为上限的零点八倍。

活文档的度量范围：`skill`、`agents`、`global` 三个目录下的 Markdown 文件，加仓库根目录下除变更记录外的 Markdown 文件；变更记录即 `CHANGELOG.md` 不计入。该范围使随位置迁移的文档仍受同一阈值管辖，不因换位而脱离度量。

默认：上表未列出的结构事实不由 `code-health.js` 输出，须由审计代理语义判定；活文档规模已列入上表文件规模类，由 `code-health.js` 度量。

度量仅报告不阻断，其阻断地位由 G5-INT 的治理条件承接。度量恶化的具体项写入审计报告的必填节。

脚本消费契约表，消费方按本表解析各脚本的末行结论、退出码与门禁地位：

| 脚本 | 输出形态 | 机读结论 | 退出码 | 门禁地位 | 输出上限 |
|---|---|---|---|---|---|
| trace-check.js | 文本正文 | 末行 `RESULT: pass` 或 `RESULT: gap` | 0 通过，1 存在缺口 | G2、G4 与 G5 门禁 | 12000 字节 |
| code-health.js | 文本正文 | 末行 `RESULT: report` | 恒 0 | 仅报告，不作门禁 | 12000 字节 |
| governance-check.js | 单 JSON | `verdict` 字段 | 0 通过，1 阻断 | G5-INT 门槛 | 12000 字节 |
| ref-check.js | 文本正文 | 末行 `RESULT: pass` 或 `RESULT: drift` | 0 通过，1 存在漂移 | 本仓库文档同步链 | 12000 字节 |
| debt-check.js | 文本正文；并写 `docs/debt-history.json` 债务快照 | 末行 `RESULT: pass` 或 `RESULT: overdue` | 0 通过，1 存在缺口（超期、超上限或字段不全） | 交付门前置校验 | 12000 字节 |
| metrics-report.js | 文本正文 | 末行 `RESULT: report` | 恒 0 | 仅报告，不作门禁 | 12000 字节 |

默认：未列入本表的脚本不构成任何门的证据。

trace-check 的判域在原有三层链路外补三层，末行结论与退出码语义不变。**R 编号机械追溯**：每条 R 须至少被一条 AC 承接，未被承接报覆盖缺口；每条 AC「对应需求」列引用的 R 须在 REQUIREMENTS.md 需求清单中真实存在，不存在者报悬空；编号形态由需求清单实得编号归纳，不预设前缀恒常与编号连续，识别不出编号体系或缺 REQUIREMENTS.md 时报「无法判定」并说明该断言未执行。**孤儿与悬空**：未声明需求编号或编号列为空的 AC 报孤儿；DESIGN「对外接口与约定」契约表出现的接口，在三层链路中无可机械判定的来源形态时报「无法判定」并说明；契约表消费方列的取值能对应项目根下目录或文件者通过，路径形态而不存在者报悬空，逻辑模块名而非路径者报「无法判定」，不得以模糊匹配猜测。**术语拼写一致性**：同一模块名在 DESIGN 消费方列、代码目录树与 TEST_PLAN 路径三面拼写一致，判定为去分隔符、转小写归一为同一键后逐字等值比较，键内原始拼写跨两个以上面出现两种以上拼写即报，不使用相似度阈值，只判拼写不判语义漂移。新增判据无可机械判定形态时一律报「无法判定」，作告警而非缺口，末行仍为 `RESULT: pass`。

甲类脚本的调用一律由根会话经对应 `ddd_*` 工具，`root` 传被开发项目根的绝对路径，不再拼路径，故 G5 的机械证据由根会话运行产出，不接受实现者自陈；乙类与丙类脚本由维护者在本仓库内执行，调用边界见 `SKILL.md` 的机械门禁；输出上限按 UTF-8 字节计量，超限时截断明细，末行机读结论必须保留且完整。

`ddd_governance_check` 工具（`root` 传被开发项目根的绝对路径）输出单项 JSON verdict：每份 DESIGN.md 的契约指纹已记录且与契约段实算值相同，`docs/health.json` 最新一条相对上一条问题类计数未上升，且存在设计文档树时其根路径已在 ARCHITECTURE 声明，三者同时成立时 verdict 为 `ok`，否则为 `blocked`；无设计文档树时零考察，verdict 为 `ok`。问题类计数指超限类、死代码类与注释质量类，其键集合以该脚本内的单一常量为唯一权威，本节只作抽象描述而不另行罗列键名；接近上限类属预警阈值、未构成问题，弱信号重复类需语义判定，二者不参与阻断，只在脚本输出的报告中列出；`docs/health.json` 不存在时不判趋势。它作为 G5-INT 的门槛证据，退出码非零即 blocked；命令路径可确定时可经 typed gate 挂载。
