## 12. 声明面可验证与修剪

**铁律：不被消费的声明是危险的，因为无人验证其正确性。**

- [ ] 每条声明同时具备消费方与验证手段，缺一不得引入。

声明面包括接口契约、公开导出、能力清单、规则条款、配置项、模板字段与依赖项。本条的执行入口为 G6，即审计报告未过则不得交付。

审计类代理必须全量核对，不得因看似无用、低风险或成本高而跳过；对每项回答是否被消费与消费是否正确；发现无消费方声明即报缺陷，不得静默留存；反向抽查不少于三项并实测消费路径真的通，专项审计可自行提高下限。

审计必须同时核验**变更记录当轮声称与实际产物是否相符**，声称与实际不符即为缺陷，与代码缺陷同级处理。

无用代码与冗余声明必须删除，不得注释保留，不得以将来可能用到为由滞留。**写入者的清理义务范围限于所触及文件内的连续注释代码与兼容层标记，即文件级属性；无引用文件属仓库级属性，由审计代理处理，不入写入义务。**删除前确认无消费方并登记变更记录。义务的完整性见「结构与契约的演进治理」节的触碰即治理。

写入者的清理义务触发点：结构健康度量显示恶化时、G6 交付前、需求变更后、能力新增后、版本收尾、重建完成后。

审计报告由审计代理在标题下方给出建议归档名，格式为 G6-序号-版本，**序号取 docs/audits/ 现存最大序号加一**；审计代理为只读，**落盘由根会话执行**，写入 `<项目根>/docs/audits/`。**修剪清单在下次审计时必须逐项回验是否真的删除**，回验输入取自该目录内上一份报告。

pi 运行时契约类声明，如 worktree、control 字段与 frontmatter 字段，以冒烟检查与运行时观察为验证手段，不因无法离线验证而判为纸面消费方。

## 13. 结构与注释的机械证据

`node ~/.pi/agent/skills/ddd-methodology/scripts/code-health.js <项目根>` 输出五类事实，作为 G5-INT 的证据源与 G6 审计的输入。度量写入 `<项目根>/docs/health.json`，**该文件入版本管理作为趋势证据，历史上限 50 条**，超出由脚本截断。

| 类别 | 覆盖的事实 | 机械程度 |
|---|---|---|
| 文件规模 | 超 500 行的代码文件、基础或核心模块文件超 300 行、活文档超 200 行、各类接近上限文件 | 完全 |
| 死代码 | 连续注释代码块、兼容层标记、无引用文件 | 大致，不可达分支需 AST 故未覆盖 |
| 重复嫌疑 | 同名声明跳文件出现 | 弱信号，语义级重复需审计代理判定 |
| 注释 | 违禁模式与提及已不存在标识符的过时引用 | 部分，是否解释为什么不可机械判定，由审计代理抽检 |
| 结构趋势 | 被触碰文件的规模变化，超阈值文件数相对上轮的增减 | 完全 |

度量落盘的活文档三字段：`docFiles` 为纳入度量的活文档份数，`docOversized` 为行数超文档阈值的活文档数，`docNearLimit` 为行数接近文档阈值的活文档数；文档超限与接近上限仅报告不阻断，其文档阈值与承载体见「机械约束」节。

默认：上表未列出的结构事实不由 `code-health.js` 输出，须由审计代理语义判定；活文档规模已列入上表文件规模类，由 `code-health.js` 度量。

度量仅报告不阻断，其阻断地位由 G5-INT 的治理条件承接。度量恶化的具体项写入审计报告的必填节。

脚本消费契约表，消费方按本表解析各脚本的末行结论、退出码与门禁地位：

| 脚本 | 输出形态 | 机读结论 | 退出码 | 门禁地位 | 输出上限 |
|---|---|---|---|---|---|
| trace-check.js | 文本正文 | 末行 `RESULT: pass` 或 `RESULT: gap` | 0 通过，1 存在缺口 | G4 与 G5 门禁 | 12000 字节 |
| code-health.js | 文本正文 | 末行 `RESULT: report` | 恒 0 | 仅报告，不作门禁 | 12000 字节 |
| governance-check.js | 单 JSON | `verdict` 字段 | 0 通过，1 阻断 | G5-INT 门槛 | 12000 字节 |
| ref-check.js | 文本正文 | 末行 `RESULT: pass` 或 `RESULT: drift` | 0 通过，1 存在漂移 | 本仓库文档同步链 | 12000 字节 |

默认：未列入本表的脚本不构成任何门的证据。

各脚本的调用形式统一为 `node ~/.pi/agent/skills/ddd-methodology/scripts/<脚本名>.js <项目根>`；输出上限按 UTF-8 字节计量，超限时截断明细，末行机读结论必须保留且完整。

`node ~/.pi/agent/skills/ddd-methodology/scripts/governance-check.js <项目根>` 输出单项 JSON verdict：每份 DESIGN.md 的契约指纹已记录且与契约段实算值相同，且 `docs/health.json` 最新一条的超阈值文件数不高于上一条时 verdict 为 `ok`，否则为 `blocked`。它作为 G5-INT 的门槛证据，退出码非零即 blocked；命令路径可确定时可经 typed gate 挂载。
