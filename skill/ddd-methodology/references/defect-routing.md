# 缺陷四级路由细则

## 判定流程

代理6 执行测试失败时执行。

```
测试失败
 ├─ 复核测试计划：计划漏场景/断言错/覆盖缺口？
 │    └─ 是 → D 测试级：派 ddd-fixer 修计划 → 代理6 重跑
 ├─ 比对代码与 DESIGN.md：实现是否偏离设计？
 │    └─ 是 → C 实现级：派 ddd-fixer 修码（不改设计）→ 重跑
 ├─ 评审设计自洽性：设计矛盾/边界不清/接口不匹配/实现者"做不出来"？
 │    └─ 是 → B 设计级：代理2/3 修订设计 + 同步修订模块 AC → 重新走实现
 └─ 设计正确执行后仍不满足总 AC？
      └─ 是 → A 需求级：回代理1 → 与用户确认 → 修订需求与总 AC
```

**核心规则**：默认最低层 D/C 判定；低层自检通过仍失败才上移一层。仅 B 级及以上才回设计层，小缺陷就地修复。

**仲裁**：定级争议由根会话仲裁；仲裁不了升级用户。

**终止条件**：同一缺陷轮回修复超过 2 轮仍未解决 → 强制升级用户，禁止继续循环。

## 路由责任矩阵

| 级别 | 定级者 | 修复者 | 修订文档 | 是否回用户 |
|---|---|---|---|---|
| A 需求级 | 代理6 提出，代理1 复核 | 代理1 | REQUIREMENTS.md + AC.md | ✅ 必须确认 |
| B 设计级 | 代理6 提出，代理2/3 复核 | 代理2/3 | DESIGN.md + 模块 AC，必要时含 ARCHITECTURE.md | 重大变更时 |
| C 实现级 | 代理6 | ddd-fixer，代理4 可就地修 | 无 | ❌ |
| D 测试级 | 代理6 | ddd-fixer，代理5 可就地修 | TEST_PLAN.md | ❌ |
| G4.5 接口评审缺陷 | ddd-interface-reviewer 提出，根会话复核 | 视严重度：接口设计问题→代理3，定 B 级；文档瑕疵→代理3就地修 | DESIGN.md 接口契约 | 设计级必须修复项冻结前必须清零 |
