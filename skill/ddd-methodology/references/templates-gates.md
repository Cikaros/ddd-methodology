# 门禁与缺陷记录模板

本文件承载门禁检查单与缺陷路由单两个过程记录模板，产物模板见 `templates.md`。

## 门禁检查单

写入 `<项目根>/docs/gates/G{门号}-记录.md`。检查项逐字取自规范「质量门禁」节门禁表的退出条件子项，不得另写一套，也不得概括。记录须含机读行 `GATE: {"id":"G{门号}","round":<过门轮次>,"verdict":"<pass|fail>"}`：`round` 为过门轮次，首次过门为一、因退回而重过递增；`verdict` 取 `pass`（通过）或 `fail`（退回）。该行由度量的八道门一次通过率与过门轮次采集。机械证据的运行方须登入记录，指明实际运行工具或脚本者，不得留空或以工具名替代。

```markdown
# G{门号} 记录

- 过门时间：
- 机读行：`GATE: {"id":"G{门号}","round":1,"verdict":"pass"}`
- 机械证据运行方：{运行该机械证据的主体，如根会话}
- 退出条件逐条核对：
  - [ ] 按门禁表逐项抄录退出条件子项，每项一行
- 证据源输出：
  - 机械工具或脚本命令类：附运行输出全文
  - 指名代理类：附代理报告的判据段
- 结论：通过 / 退回，退回注明对象与原因
```

G4 与 G5 附由根会话运行的 trace-check 输出，其中含契约指纹校验结果；G4.5 记录附契约指纹；G5-INT 附 code-health 输出、governance-check 的 verdict 与结构治理回执；G6 附审计报告全文，报告节次以审计代理输出契约为准。

审计报告由根会话按报告给出的建议归档名落盘至 `<项目根>/docs/audits/`，命名格式为 G6-序号-版本，作为下次回验的输入。
