# 门禁与缺陷记录模板

本文件承载门禁检查单与缺陷路由单两个过程记录模板，产物模板见 `templates.md`。

## 门禁检查单

写入 `<项目根>/docs/gates/G{门号}-记录.md`。检查项逐字取自规范「质量门禁」节门禁表的退出条件子项，不得另写一套，也不得概括。记录须含机读行 `GATE: {"id":"G{门号}","round":<过门轮次>,"verdict":"<pass|fail>"}`：`round` 为过门轮次，首次过门为一、因退回而重过递增；`verdict` 取 `pass`（通过）或 `fail`（退回）。该行由度量的八道门一次通过率与过门轮次采集。机械证据运行方的登记要求见规范「质量门禁」节。

```markdown
# G{门号} 记录

- 过门时间：
- 机读行：`GATE: {"id":"G{门号}","round":1,"verdict":"pass"}`
- 机械证据运行方：{运行该机械证据的主体，如根会话}
- 退出条件逐条核对：
  - [ ] 按门禁表逐项抄录退出条件子项，每项一行
- 证据源输出：
  - 机械工具或脚本命令类：附运行输出全文
  - 指名代理类：附代理报告的判据段
- 结论：通过 / 退回，退回注明对象与原因
```

G4 与 G5 附由根会话运行的 trace-check 输出，其中含契约指纹校验结果；G4.5 记录附契约指纹；G5-INT 附 code-health 输出、governance-check 的 verdict 与结构治理回执；G6 附审计报告全文，报告节次以审计代理输出契约为准。

审计报告由根会话按报告给出的建议归档名落盘至 `<项目根>/docs/audits/`，命名格式为 G6-序号-版本，作为下次回验的输入。

## 任务树模板

### 根索引 BOARD.md

置于 `<项目根>/docs/board/BOARD.md`，唯一写者为根会话，承载根节点、里程碑节点与收口标记。

```markdown
# 任务看板

## 根节点与里程碑

| 节点编号 | 父节点 | 类型 | 确定度 | 状态 | 覆盖范围 | 证据指针或引用 | 登记信息 |
|---|---|---|---|---|---|---|---|
| ROOT | 无 | 里程碑 | 已确定 | 进行中 | 项目根 | 无 | 周期开始 |
| M-01 | ROOT | 里程碑 | 已确定 | 进行中 | `core/http/` | 无 | 依据 R-003 |

## 收口标记

每条里程碑收口一行，机读行形态固定：

`BOARD: {"milestone":"M-01","status":"closed","round":1}`

```

### 模块节点 NODES.md

置于 `<项目根>/docs/board/<模块路径>/NODES.md`，路径与 `docs/design/` 同构，唯一写者为该模块 writer。

```markdown
# 节点：模块名

| 节点编号 | 父节点 | 类型 | 确定度 | 状态 | 覆盖范围 | 证据指针或引用 | 登记信息 |
|---|---|---|---|---|---|---|---|
| OB-01 | M-01 | 义务 | 已确定 | 未开始 | `core/http.ts` | 无 | 依据 DESIGN 的对外接口与约定节 |
| EX-01 | M-01 | 执行 | 待定 | 未开始 | `core/http.ts` | 无 | 新增于推进期，承接方 ddd-implementer |
```

字段取值：类型取里程碑、模块、义务、执行四值；确定度取待定、已确定两值；状态取未开始、进行中、已核销、不适用、已废弃五值。覆盖范围来源限定为 DESIGN 的「实现文件粒度预判」表。已核销为终态，不得修改、拓展与回退，变更一律新建节点。完整规则见规范「接口先行与冻结」节的义务核销条。
