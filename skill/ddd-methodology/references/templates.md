# 文档模板库

## REQUIREMENTS.md（代理1 产出）

```markdown
# 需求文档

## 项目类型判定
- [ ] 新建项目 / 二次开发项目（判定依据：）

## 需求清单
| 编号 | 需求描述 | 优先级 | 状态（已确认/待确认） |

## 已澄清的问题记录
| 原始模糊点 | 澄清结论 | 用户确认时间 |

## 非功能需求
（性能/安全/兼容性等）

## 需求对齐声明
> 本需求已与用户逐条确认对齐，可作为设计与验收的唯一需求来源。
```

## AC.md（代理0 产出）

```markdown
# 验收标准（总）

## AC-001: <名称>
- Given <前置条件>
- When <操作>
- Then <可观测结果>

> 模块级 AC 由代理3 拆分后写入对应目录 DESIGN.md 的"模块级验收要点"。
```

## ARCHITECTURE.md（代理2 产出）

```markdown
# 架构设计

## 技术环境
（语言、运行时、框架、构建工具、测试框架及版本）

## 目录规划
（目录树 + 每个顶层目录一句话职责；符合该语言大众编排习惯）

## 横切规范（集中定义，模块文档只写差异）
- 日志规范：
- 异常处理规范：
- 命名规范：
- 其他横切关注点：

## 二次开发现状分析（仅限缺少规范文档的二次开发项目）
- 原项目结构与技术准则提炼：
- 新模块与原结构的同构约束：
```

## DESIGN.md（代理3 产出，每目录一份）

```markdown
# DESIGN：<模块名>

## 职责描述
## 能力范围
- 做：
- 不做：
## 对外接口/约定
## 依赖约束
（允许依赖谁、禁止依赖谁）
## 模块级验收要点
（从总 AC 拆分而来的 G/W/T 条目）
## 变更记录
| 版本 | 说明 |
```

## TEST_PLAN.md（代理5 产出，与设计树同构）

```markdown
# TEST_PLAN：<模块名>

## 测试范围
（对应 DESIGN.md 的能力范围与验收要点）

## 用例清单
| 用例ID | 覆盖的 AC/验收要点 | 前置 | 步骤 | 断言 | 优先级 |

## 缺陷记录与路由
| 缺陷ID | 级别(A/B/C/D) | 定级依据 | 路由去向 | 状态 |
```

## 缺陷路由单（代理6 产出）

```markdown
# 缺陷路由单：<缺陷ID>
- 现象：
- 定级自检：C级（代码 vs 设计一致性）：；B级（设计自洽性）：；A级（满足 AC）：；D级（计划缺陷）：
- 判定级别与依据：
- 路由去向与处理代理：
- 轮回计数：（超过 2 轮强制升级用户）
```
