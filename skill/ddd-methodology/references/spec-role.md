本文件承载「角色与交接」节；不包含流程门禁、缺陷路由、设计粒度、变更与治理条款。

## 1. 角色与交接

派发前先回答一个问题，答否再查表；角色只由代理名标识，槽位号仅作排序。

| 槽位 | 代理 | 职责 | 产出 |
|---|---|---|---|
| 1 | ddd-requirements | 细化需求，与用户确认对齐，判定新建或二次开发 | REQUIREMENTS.md |
| 2 | ddd-acceptance | 需求转可执行验收标准 | AC.md |
| 3 | ddd-architect | 技术环境、目录规划、横切规范、基础能力清单、改造影响评估 | ARCHITECTURE.md |
| 4 | ddd-decomposer | 目录同构设计文档树，签名级接口契约 | docs/design/**/DESIGN.md |
| 4.5 | ddd-interface-reviewer | 接口契约独立交叉评审，只读 | 接口评审报告 |
| 5 | ddd-implementer | 按就近设计实现代码与单元测试 | 各目录代码与测试 |
| 6 | ddd-test-planner | 制定单元测试计划树 | docs/test/**/TEST_PLAN.md |
| 7 | ddd-fixer | 集成收口与按路由单修 C 级代码或 D 级计划 | 修复清单、已尝试方案与约定遵循自检 |
| 8 | ddd-tester | 执行测试，缺陷定级路由 | 测试报告与缺陷路由单 |
| 9 | ddd-arbiter | 定级争议独立仲裁，只读 | 仲裁裁决单 |
| 10 | ddd-doc-sync | 文档一致性巡检，只读 | 漂移清单 |
| 11 | ddd-auditor | 声明面与死代码审计，只读 | 审计报告与修剪清单 |

槽位号为流程位置与排序标识，跨文档引用一律用代理名。代理名是唯一键。

交接链：需求 → 验收 → 架构 → 分解设计 → 接口冻结 → 实现 ∥ 测试规划 → 集成收口 → 测试执行 → 声明面审计。测试执行与实现永不同段。

根会话保留调度、仲裁、用户裁决与最终验收权，不承担实现类工作。

**派发判定。** 第一问固定为「这个任务是只读的吗」。回答是则派 scout，不再查表。

回答否，按产出物查下表选承接者。

| 产出物 | 承接者 |
|---|---|
| 需求文档 | ddd-requirements |
| 验收标准 | ddd-acceptance |
| 架构文档 | ddd-architect |
| 分解设计与 DESIGN 修订 | ddd-decomposer |
| 接口评审报告 | ddd-interface-reviewer |
| 代码与单元测试 | ddd-implementer |
| 测试计划 | ddd-test-planner |
| 测试报告与缺陷路由单 | ddd-tester |
| 缺陷修复与集成收口 | ddd-fixer |
| 仲裁裁决单 | ddd-arbiter |
| 文档巡检报告 | ddd-doc-sync |
| 审计报告 | ddd-auditor |
| 代码评审 | reviewer |
| 无匹配产出物 | 根会话直接完成 |

表后三条禁令：

1. 只读任务不得派给任何具备写权限的 ddd-* 代理，即使任务看上去很小。
2. 承接者收到不符合自身职责的任务时停止并报告「派发类型不匹配」，注明缺失的前置输入，不得改换任务性质后推进。
3. 该拒绝导致该次子任务验收判 rejected，属预期信号而非代理异常，根会话据此改派或补足前置输入。

承接者合法拒绝任务时，其验收因必需要求项未被满足而判 rejected，这是预期信号而非代理失败：根会话应据拒绝理由改派或补足前置输入，不得要求执行者将就，不得据此认定代理异常。加速档各阶段的任务文本由固定模板给出且输入完整，不触发该情形。

scout 与 reviewer 由 pi-subagents 随带，不在本方法论的十二个代理清单内，派发时使用准确名称 scout 与 reviewer，不加 ddd- 前缀。
