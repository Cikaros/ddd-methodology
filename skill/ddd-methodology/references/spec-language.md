## 20. 表述与术语

文档服务两类读者：当天要动手的维护者与首次进入项目的人。生涩词汇压缩了信息，也抬高门槛，代价由后来者承担。本节给出四条取向与四项判据，使术语从听起来专业变为有定义、有例子、能落地。

四条取向：

1. **分层表述**：先摘要后细节，摘要不超过三行。
2. **术语有据**：每个术语有定义、有例子、有落地锚点。
3. **词汇分类**：领域标准词与自造词分列，自造词须自证。
4. **副本受控**：白话解释是权威文档的抽取，不手工分叉。

### 20.1 分层表述与摘要

核心文档在标题下方先给摘要，再展开细节。三项判据同时成立方可。

| 判据 | 内容 |
|---|---|
| 长度 | 不超过三行 |
| 用词 | 不含术语表未登记的术语 |
| 索引性 | 每条指向本文后续节次或编号 |

适用范围为 `REQUIREMENTS.md`、`ARCHITECTURE.md` 与每份 DESIGN；表格式产物 `AC.md` 与 `TEST_PLAN.md` 不适用。字段形态见 `templates.md` 中各产物模板节，本节不重述。

`ARCHITECTURE.md` 另含「项目速览」节，面向首次进入项目者，不受三行限制，但不复述正文细节；摘要与项目速览共同承担新人可读，不另产独立文档。

摘要不替代正文，正文的判据强度也不因摘要而降低。

### 20.2 术语表

术语表置于项目根 `GLOSSARY.md`，是本项目术语的唯一权威处，DESIGN 与其余文档只引用不复制。

**产出强制，表不可为空。** 项目无论大小均须产出该文件；项目确无自造概念时，最小形态为收录领域标准词。条目取自已产出的 `REQUIREMENTS.md`、`AC.md`、`ARCHITECTURE.md` 或 DESIGN 正文，禁止为填表虚构词条。

字段固定六列。

| 列 | 含义 |
|---|---|
| 术语 | 表中唯一，一义不得两名 |
| 类别 | 取领域标准词、项目术语、自造词三值之一 |
| 指什么 | 一句定义，说明所指 |
| 不指什么 | 说明排除项，仅同名异义者必填 |
| 落地锚点 | 该术语在代码侧或测试侧的可解析位置 |
| 白话解释 | 面向首次进入项目者的解释，不含未登记术语；自造词的该列须含至少一个具体例子 |

**类别与必填项。** 三类各有必填项。

| 类别 | 必填项 | 判据 |
|---|---|---|
| 领域标准词 | 权威来源 | 定义与该领域公认出处一致 |
| 项目术语 | 定义与落地锚点 | 所指在本项目内唯一 |
| 自造词 | 定义与落地锚点，且白话解释含至少一个例子 | 领域权威与语言标准中查无同名者 |

未命中上表任何一行时不引入该词，改用已登记术语或领域标准词表述。

**落地锚点。** 取值须解析到下列四者之一：代码模块或文件、对外接口、测试用例或测试文件、监控指标。四者皆无者不是术语，是无消费方的声明。

**粒度。** 术语表计入「粒度与独立性」节的文档粒度阈值，与其他活文档同口径；超过阈值时按领域拆分为 `docs/glossary/` 下的分类文件，`GLOSSARY.md` 只留索引与拆解说明。

**维护责任。** 术语表的触发点与承接方与项目级指令文件同构，见「项目级指令文件的维护」节，本节不重述。各写入者不得各自追加；分解设计期新出现的术语在就近 DESIGN 内标注，由根会话在迭代收尾汇总入表。

### 20.3 术语的消费与定级

术语条目是一项声明，其消费方与验证手段的判据见「声明面可验证与修剪」节；术语有定义而落地锚点缺失者，按该节的无消费方声明处置。

术语与既有机械校验分工：规范「结构与注释的机械证据」节所列拼写一致性判定只判同一模块名跨文档的拼写形态，本节管定义与落地。两者判域不同，不得相互替代，也不得把语义漂移并入拼写判定。

缺陷定级见下表，其余形态按「缺陷四级路由」节定级。

| 形态 | 级别 |
|---|---|
| 自造词未在术语表登记 | B 级设计缺口 |
| 领域标准词用法与公认定义相悖 | C 级实现偏离 |
| 术语有定义而落地锚点缺失 | 按无消费方声明处置 |

默认：术语用语与既有登记一致时不报缺陷，措辞差异不计。

### 20.4 产出者自检

产出核心文档的代理在完成报告的约定遵循自检段内列出本文档出现的术语，标明项目术语与自造词；自造词须已在术语表登记，未登记即按本节定级表处置。

审计代理在声明面审计中核对术语条目：消费方判据为该术语真实出现在已产出的需求、验收、架构或设计正文中，验证手段判据为其落地锚点真实存在。
