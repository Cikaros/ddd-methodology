# 子项目设计：@cikaros/ddd-methodology（Hermess 2.0）

## 定位与边界

- **本子项目产出的是环境，不是功能**：一个可装入 OpenCode 的插件包，装入后在**当前项目根**搭起设计文档骨架，其后按节点序列与门禁推进当前项目。
- 等式：`opencode-plugin + subagent + ddd.methodology = Hermess`。
- **边界内**：插件包本体（`src/`）、随包内容层（`skills/`、`agents/`、`assets/`）、随包工具（`scripts/`）；以及本仓自身作为「项目」的文档树（`docs/`）。
- **边界外**：使用者项目的业务代码；模型选型与推理参数；宿主自身能力（凡宿主已提供者，一律对接而非自建，见概要设计 §十六）。

## 四级同构映射

`docs/ddd/<X>` 与仓库根 `<X>` 一一对应。本子项目的模块层、分组层、文件层落点如下（清单在模块级各自维护，本件不复写具体条目）：

| 级 | 设计件 | 对应实物 |
|---|---|---|
| 子项目 | `docs/ddd/DESIGN.md`（本件） | 仓库根 `.` |
| 模块 | `docs/ddd/<module>/DESIGN.md` | `<module>/` |
| 分组 | `docs/ddd/<module>/.../<path>/DESIGN.md` | 该目录 |
| 文件 | `docs/ddd/<module>/.../<path>/DESIGN-<filename>.md` | 该源文件 |

## 模块清单（子项目持有）

| 模块 | 目录 | 职责 |
|---|---|---|
| 插件实现 | `src/` | server / tui / rpc 三个 part 与共享纯函数层 |
| 随包内容 | `skills/`、`agents/` | 知识层与代理定义（按需加载） |
| 随包资产 | `assets/` | **配置基线的唯一权威处**：命令注册表、门禁集、规则/记忆/套餐基线（薄文本 + 资产两态） |
| 随包工具 | `scripts/` | 离线自测与门禁读取器 |

> **单点权威**：命令注册表 / 门禁集 / 规则基线 / 记忆门槛 / 套餐，全部只在顶层 `assets/` 写具体值；`skills/`、`src/lib/registry.ts` 等一律引用不复写（M10 反漂移）。

## 依赖方向（本子项目不变量）

`docs/**`（权威）← 插件实现只读权威；随包内容与资产只依赖术语与命令注册表；`scripts/` 只读权威与实物、只写报告。**反向依赖或环即结构缺陷。**

## 承重机制承接（子项目级）

本方法论定义十一条承重机制 M1–M11（清单与判据见概要设计 §十三），另加 **M12 冻结即归并**。它们的**机械承接件**分布在各模块：

- M1/M2/M3/M9/M10 → `scripts/`（快照、变更流、落地门禁、图集重放、反漂移）
- M4/M5/M6/M7/M8/M11/M12 → `src/`（命令改造口、意图确认、记忆/看板闭环、执行规则、项目对接、归并）
