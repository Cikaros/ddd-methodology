# 落地期发现（缺陷登记册 · R36 唯一权威处）

> 对象：代码落地 + `/ddd-test` + `/ddd-validate` 的机械读数。属**临时审计件**（登记 `docs/temp.jsonl`）。
> 说明：本轮落地按 49 份文件级设计逐件实现，机械验收全绿；但**落地过程**暴露了两条设计树自身的缺陷，如实登记。

## F1 · 冻结件正文残留 `draft` 标记（**已修复**）

| 项 | 内容 |
|---|---|
| 严重度 | med |
| 判据 | 概要 §六.4：「`status: frozen` 的件不得含 `draft` 标记」 |
| 现象 | 15 份**目录级**设计件 frontmatter 已是 `status: frozen`，但 `## 状态` 正文仍字面写「本件为 `draft`…」 |
| 范围 | `docs/ddd/DESIGN.md`、`src/DESIGN.md`、`src/lib/DESIGN.md`、`assets/DESIGN.md`、`agents/DESIGN.md`、`scripts/DESIGN.md`、`skills/DESIGN.md` 及 `skills/**` 各目录级共 15 件 |
| 归因 | 冻结时只改了 frontmatter `status`，未做 M12「剔内联痕迹 / 重构成终稿」，正文状态句未同步 |
| 处置 | **已修复**：`## 状态` 正文统一归并为「本件为 `frozen`；与上级设计件及实物对账一致。」（非契约叙述，契约（frontmatter/target）逐字未动） |
| 复检 | body `draft` 标记件数：15 → **0** |

> **自审计漏检根因**：原自审计检查项只做 `^status:\s*draft`（frontmatter 行）扫描，未扫**正文**状态句；M12「内联痕迹」清单未含「正文状态句」。

## F2 · `scripts` 模块承重承接超越其文件级实证（**未闭合**）

| 项 | 内容 |
|---|---|
| 严重度 | high（涉及多项「保留核心」） |
| 判据 | R13/R20 声明面与实物对账「声明了但实物没有」；§十三 承重机制须有**机械承接件** |
| 现象 | 子项目设计称「M1/M2/M3/M9/M10 → `scripts/`（快照、变更流、落地门禁、图集重放、反漂移）」，`scripts/DESIGN.md` 亦称承 M1/M2/M3/M9/M10；但 `scripts/` 仅有 `selftest.mjs`、`board.mjs` 两件文件级设计与实现 |
| 缺件（无文件级设计、无实现） | ① **M1** 设计树机器可读快照（`snapshot`）；② **M2** 变更流 `docs/CHANGELOG.jsonl` **唯一写入器**（R27，保留核心）；③ **M9** 图集重放与巡检（R35，保留核心）；④ **M10** 反漂移**复写扫描**（仅有 `registry.ts` 清单单点，无独立扫描器）；另 `scripts/DESIGN.md` 声称的「门禁读取器」亦无对应件 |
| 连带 | `assets/bottom-lines.json` 的 `BL-consolidate-no-delete` 以「除唯一工具」为前提写保护 `CHANGELOG.jsonl`，但**唯一工具尚无设计/实现**；`package.json` 亦无 `change`/`map`/`validate` 脚本入口 |
| 其它未承载项 | **R25** 判据与反证成对（违规样本集）在设计树**未被提及**；**R36** 缺陷登记册（本件即其首个实例）在 `docs/ddd/**` 无对应文件级设计 |
| 归因 | 概要 §8.9 包骨架只列 `selftest.mjs`；文件级设计按此落地——**模块设计沿用了 §十三 的完整承重清单，超出包骨架与文件级设计所能实证的范围**（模块级 over-claim） |
| 处置 | **未闭合**。两条出路（待裁决）：**(A) 补齐**——为 M1/M2/M9（＋R25/R36）补文件级设计 + 测试件 + 实现（`scripts/{snapshot,change,map,drift-check,counterexamples}.mjs` 及以上四类）；**(B) 收窄声明**——把模块/子项目设计中的承重承接改为如实表述（哪些已承接、哪些待承接），使声明面=实物面 |
| 复检判据 | 选项 A：`target` 与实物一致、G3 对账零失败、补件过离线自测；选项 B：声明面与实物面双向对账零失败（R20） |

> **自审计漏检根因**：原自审计检查项 #6 只验「M1–M13 是否在树中被**提及**」，未验「每个承重机制是否有**具名文件级承接设计**且实物存在」。这是「提及 vs 承接」的判据强度不足。
