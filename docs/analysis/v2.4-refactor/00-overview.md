# v2.4 Agent 优先推理改造总览

本轮改造把本方法论的规范、代理、入口与工具面，从「人工同步的多副本结构」改为「单一权威加就近送达加机械校验」。目标是让使用本方法论的 LLM Agent 不必在生成动作前先做条件配对、顺序记忆、权威裁决或跨文件拼装。

上一轮改造设计见 `docs/analysis/method-versioning-governance.md`，本轮是其同一脉络的延续，受力点在「可被 Agent 直接执行」而非「可被人工维护」。

## 1. 问题

四类根因，均有只读调研证据，证据来源为 4 份 scout 报告与历史审计归档。

| 根因 | 表现 | 量化证据 |
|---|---|---|
| 权威分散 | 同一规则多处并存，Agent 须自行裁决哪处为准 | 派发判定 4 处、四级判据 2 至 4 处、契约指纹 4 至 7 处、粒度阈值 7 处以上、阶段流 4 处、结构治理回执句 5 处逐字重复 |
| 引用人工同步 | 章节号、阶段键、阈值、守卫编号靠人工维护，插节必漏 | `SKILL.md` 19 处 `§N`、`agents` 10 处、`spec` 6 处、`templates` 2 处；CHANGELOG 中编号同步与交叉引用顺延各跨 4 个版本 |
| 判定多维缺默认 | Agent 须同时持有两个以上维度才能选出动作，且无兜底分支 | 门禁表三轴、四级路由四列加表外倒序、改造分级双入口、派发判定双维、守卫 H-1 五维、H-2 双条件 |
| 声明执行错位 | 文档声明的机械承载实际未运转，或行为与文字不同 | trace-check 被声明为 G4 与 G5 证据源而 workflow 从不调用；接口门文字承诺退回而脚本中断；code-health 列为证据源却恒退出 0 |

历史反复修补未根治的四类问题依次为冗余副本、声明执行错位、人工引用同步、无消费方声明。最有效的降负手段是合并为单一权威源、关键规则内联、判定表化、用机械证据替代语义判断。

## 2. 设计原则

三条原则贯穿全部落点，冲突时按序优先。

1. **判据就近，权威单一。** Agent 完成本职所需的判据必须在其常驻视窗内。同一规则的实体定义只允许存在一处，即权威位置。
2. **内联即副本，副本受机械校验。** 代理提示词中的内联摘要属既定送达机制，不算漂移，但必须与权威源逐字或语义一致，且这种一致由脚本校验，不靠人工同步。
3. **显式优于隐含。** 顺序、默认、优先级、生效范围一律写出。判定表必须有默认分支。

## 4. 关键设计决策

| 决策 | 取舍 |
|---|---|
| 不引入面向 Agent 的数字规则 ID | 数字 ID 对 LLM 是额外记忆负担。改用语义化节名引用，即 `见「节标题」节`，节号仅作排序标识保留 |
| 跨文档一致由脚本硬编码事实集校验 | 校验器内置阈值集、门号集、阶段键集、代理名集、脚本名集，无需文档登记 ID |
| 门禁编号保留 G1 至 G6 含 G4.5 与 G5-INT | 重编号会破坏既有 `docs/gates/` 记录与外部引用。改为新增序号列，流程按序号推进 |
| 挂门判定改为例外清单 | 默认全部强制条款均已挂门，仅在 `spec` 列出未挂门的指导性条款。元判断成本从逐条归属降为对清单查表 |
| 脚本输出格式不强制统一为 JSON | code-health 的人类可读报告有实际价值。改为统一末行机读结论加一张脚本消费契约表，明确退出码语义与门禁地位 |
| workflow 补齐至九步并接入脚本门禁 | 消除加速档与主流程的步数差异，该差异本身是负担 |

## 5. 验收标准

| 编号 | 验收要点 | 判定方式 |
|---|---|---|
| AC-1 | 任一代理完成本职所需判据均在其提示词内，跳转只用于权威细节 | 逐代理核对，内联段落自足 |
| AC-2 | 任一规则的实体定义全仓库只出现一处，其余为内联摘要 | `ref-check` 校验加人工抽查 |
| AC-3 | 全部判定表含默认分支，全部顺序规则以显式步骤表达 | 运行 `node scripts/ref-check.js .` 的 C10 项，辅以人工抽查 |
| AC-4 | 引用失效与常量漂移可被脚本机械检出 | 运行 `ref-check.js` |
| AC-5 | 脚本消费契约表存在且与脚本实际行为一致 | 运行三脚本比对输出与表 |
| AC-6 | workflow 阶段集合与 `SKILL.md` 流程集合一致，阶段键唯一 | `ref-check` 校验加人工核对 |
| AC-7 | 无明显新增无消费方声明 | 派 `ddd-auditor` 审计 |

## 7. 影响面与兼容性

改动 17 个文档、5 个核心脚本或工具文件与 4 个安装卸载脚本。对外行为无破坏性变更，`.ddd-state.json` 的既有阶段键集合保持兼容，`docs/gates/` 既有记录仍可读。新增 `docs/analysis/v2.4-refactor/` 六份设计文档与 `scripts/ref-check.js`。

版本定为 v2.4.0，属结构性改动。
