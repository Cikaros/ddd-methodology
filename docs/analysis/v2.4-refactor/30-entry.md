# 入口与模板改造契约

对象文件：`skill/ddd-methodology/SKILL.md`、`skill/ddd-methodology/references/templates.md`、`global/APPEND_SYSTEM.md`、`README.md`。

## 1. SKILL.md

### 1.1 目标形态

节序固定如下。

```
知识加载规则
流程
条件加载判定
根会话职责
机械门禁
Workflow 加速档
派发要求
```

### 1.2 知识加载规则

三层送达保留，并补两条显式规则。

1. 优先级：代理侧内联高于流程内联标注，流程内联标注高于规范深读。冲突时以更靠前者为准。
2. 主体范围：「禁止整卷加载 references」只约束子代理。根会话常驻上下文为 `references/spec.md` 与本文件。

### 1.3 流程

九步改为表格。列为序号、阶段、代理、产出、门、必读、条件读。内容取自现文九步，加载项拆入必读与条件读两列。

序号、阶段、代理、门的固定值如下。

| 序号 | 阶段 | 代理 | 门 |
|---|---|---|---|
| 1 | 需求采集 | ddd-requirements | G1 |
| 2 | 验收标准 | ddd-acceptance | G2 |
| 3 | 架构设计 | ddd-architect | G3 |
| 4 | 分解设计 | ddd-decomposer | G4 |
| 5 | 接口冻结 | ddd-interface-reviewer | G4.5 |
| 6 | 实现与测试规划并行 | ddd-implementer 与 ddd-test-planner | G5 |
| 7 | 集成收口 | ddd-fixer | G5-INT |
| 8 | 测试执行 | ddd-tester | 无 |
| 9 | 声明面审计 | ddd-auditor | G6 |

第 8 步门列写「无」，并在表后说明：「测试失败的定级与路由见规范「缺陷四级路由」节。争议时派 ddd-arbiter。」

表后一段总述门禁产物：「过门时按 templates 的门禁检查单填写，写入 `<项目根>/docs/gates/`。检查项取自规范「质量门禁」节的门禁表。」

### 1.4 条件加载判定

新增一张表，把原分散在各步的条件加载集中。列为条件、追加加载。

| 条件 | 追加加载 |
|---|---|
| 项目为二次开发 | 规范「二次开发」节 |
| 本阶段产出改造影响评估 | 规范「渐进式改造」节 |
| 产出或修订 DESIGN | 规范「粒度与独立性」节与 16.1 契约指纹条 |
| 涉及接口冻结或指纹变化 | 规范「结构与契约的演进治理」节 |
| 本阶段为集成收口或审计 | 规范「结构与注释的机械证据」节 |
| 出现定级争议 | 派 ddd-arbiter，不追加加载 |

条件判据须自足。二次开发的判据为「项目已有规范文档即为二次开发」，与 ddd-architect 的分支一致。

### 1.5 根会话职责

保留原有表述，并补入审计报告落盘义务，该义务目前只在规范中，入口未写：「审计代理为只读，其报告由你按报告给出的建议归档名落盘至 `<项目根>/docs/audits/`。」

### 1.6 机械门禁

保留声明式门禁与运行时守卫两层的说明。脚本调用形式统一为：

```
node ~/.pi/agent/skills/ddd-methodology/scripts/<脚本名>.js <项目根>
```

补一句：「脚本的输出形态、机读结论与退出码语义见规范「结构与注释的机械证据」节的脚本消费契约表。」

新增脚本 `ref-check` 的用途说明：「校验跨文档引用有效性、常量一致性与枚举集合一致性，供文档同步链使用。」

### 1.7 Workflow 加速档

1. 前置条件保持。补一条安装自检命令，在仓库内运行：`node scripts/apply-models.js status`。`apply-models.js` 不随安装复制，须在仓库在场时运行，不得写成安装后路径。
2. 补一句覆盖范围声明：「加速档覆盖九步，止于声明面审计。审计报告的落盘仍由根会话执行。」
3. 参数表化，列为参数、默认值、下界、说明。新增下表取代原散文。

| 参数 | 默认值 | 下界 | 说明 |
|---|---|---|---|
| root | 无，必填 | 无 | 项目根绝对路径 |
| maxFixRounds | 2 | 无 | C 与 D 级缺陷自动修复轮数上限 |
| stallTimeoutMs | 300000 | 30000 | 阶段停滞判定超时，单位毫秒 |

4. 接口门行为与脚本对齐，固定表述：「接口评审结论非 pass 时中断并返回本会话，由根会话决定退回分解设计或修复后重跑。」

### 1.8 派发要求

保留七要素与「一个接缝一个写入者」。派发判定句与 `global/APPEND_SYSTEM.md` 及规范「角色与交接」节保持一致，固定表述：

> 派发前先判任务类型。第一问是这个任务是只读的吗，是则一律派 scout。非只读任务按产出物查规范「角色与交接」节的派发表。承接者收到不符合自身职责的任务时停止并报告派发类型不匹配。

## 2. templates.md

1. 门禁检查单节：检查项来源固定为「逐字取自规范「质量门禁」节门禁表的退出条件子项，不得另写一套，也不得概括」。模板中的 `-[ ] 条件` 占位改为「按门禁表逐项抄录退出条件子项，每项一行」。
2. 契约指纹行：算法引用改为 `算法见规范「结构与契约的演进治理」节的契约指纹条`。
3. 缺陷路由单：`D、C、B、A 逐级结论` 改为 `按规范「缺陷四级路由」节的五步自检流程逐级记录`。
4. DESIGN 节：粒度预判字段引用与阈值锚点逐字一致，即「代码文件 500 行、基础或核心模块 300 行、文档 200 行或 10 项契约」。
5. TEST_PLAN 节：机读行 `DEFECTS: {"A":n,"B":n,"C":n,"D":n,"unresolved":bool}` 保持，并补一句该行的消费方：「该行由 workflow 加速档解析，缺行或与正文矛盾将导致中断。」
6. 顶部保留锚定说明，锚定章节名「模块级验收要点」与「用例清单」不得改写。

## 3. global/APPEND_SYSTEM.md

1. 强制中文、代码注释纪律、方法论适配三块内容保持，它们是本文件的权威内容，不在别处定义。

   - 根会话定位一句。
   - 派发两问决策与派发表指针。
   - 禁止与改派一段，含派发类型不匹配的后果链。
   - 约束六条，保持。
   - 思考前置标记一条，保持。

3. 「只读的探查、调研、方案比选、环境勘察、资料检索，一律派 scout」一句保留为权威最小判据，须包含「资料检索」，与 README 与 SKILL 版本逐字一致。
4. 保留块级标记 `<!-- ddd-methodology:begin -->` 与 `<!-- ddd-methodology:end -->`，标记内容与位置不变。
