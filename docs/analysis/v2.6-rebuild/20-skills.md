# 两个 skill 的正文契约

对象文件：`skill/ddd-rebuild/SKILL.md` 与 `skill/ddd-refactor/SKILL.md`，均为新建，各自独立目录。

## 1. 通用约定

1. 两者均设 `disable-model-invocation: true`，只由用户以 `/skill:ddd-rebuild` 与 `/skill:ddd-refactor` 显式调用。
2. 两者均不新增代理，执行复用既有的 `ddd-*` 代理。
3. 两者均以 `~/.pi/agent/skills/ddd-methodology/references/spec.md` 为规范权威源，以其 `templates.md` 为产物模板源。引用采用绝对路径形式，与既有代理的写法一致。
4. 两者正文均须自足：完成本职所需的判据内联，规范细节以指针给出。
5. 两者的绝对约束与开放区沿用总览第 3 节的分界表。

## 2. ddd-rebuild

### 2.1 frontmatter

```
name: ddd-rebuild
description: 存量重建。当用户判断项目碎片累积、修补成本已高于重建成本，需要丢弃现有架构、代码、测试与文档并整体重建时使用。仅由用户显式调用，不自动触发。
disable-model-invocation: true
```

description 须同时说明做什么与何时适用，长度不超过 1024 字符。

### 2.2 正文结构

一级标题依次为：定位、前置检查、流程、锚点冻结门、开放与约束、产物、停止条件。

### 2.3 定位

须包含下列意思，措辞可调整：「本场景用于存量重建，不是增量修补。重建意味着新产物从空开始生成，不是把旧文档拿来修订。」

### 2.4 前置检查

以编号步骤写出，与规范的存量重建节前置检查条逐字同义，并补一句停止语义：「任一步骤不通过即停止并报告，不得动工。」

### 2.5 流程

以表格给出，列固定为：序、阶段、执行者、产出、门。

| 序 | 阶段 | 执行者 | 产出 | 门 |
|---|---|---|---|---|
| 1 | 前置检查与回溯点 | 根会话 | 回溯点记录 | 硬门：版本控制在场与工作区状态 |
| 2 | 现状全量盘点 | scout | 现状盘点与锚点候选 | 无 |
| 3 | 锚点冻结 | 根会话与用户 | 冻结锚点清单 | 锚点冻结门 |
| 4 | 新设计生成 | ddd-architect 与 ddd-decomposer | 架构与设计文档树 | 接口评审门 |
| 5 | 实施 | ddd-implementer | 代码与测试 | 无 |
| 6 | 集成收口 | ddd-fixer | 集成收口结论 | 无 |
| 7 | 验证 | ddd-tester | AC 全量回归报告 | 重建验收门 |
| 8 | 审计 | ddd-auditor | 审计报告 | 审计门 |
| 9 | 废弃清除 | ddd-fixer | 废弃清单与清除记录 | 无 |
| 10 | 基线重写 | 根会话 | 架构基线 | 无 |

### 2.6 锚点冻结门

须写明：第 3 步为唯一的人工作用门，冻结前不得进入第 4 步。冻结后不得扩范围。草稿在冻结后作废。

### 2.7 开放与约束

须内联总览第 3 节的分界表，或给出等价的两列表述。

### 2.8 产物

须列出本轮产出的四件，并指向模板：回溯点记录、冻结锚点清单、废弃清单、重建验证报告。模板名见 `30-templates.md`。

### 2.9 停止条件

固定表述：「前置检查不通过、用户未确认锚点、AC 全量回归未通过、审计有阻断项时，停止并报告，不得继续后续步骤。」

## 3. ddd-refactor

### 3.1 frontmatter

```
name: ddd-refactor
description: 定向重构。当用户针对部分代码或模块在使用中发现的问题，或依据用户提出的观点，要求对架构与代码做局部重构时使用。仅由用户显式调用，不自动触发。
disable-model-invocation: true
```

### 3.2 正文结构

一级标题与 ddd-rebuild 同构：定位、前置检查、流程、锚点冻结门、开放与约束、产物、停止条件。

### 3.3 定位

须包含下列意思：「本场景用于定向重构，范围限于用户指定的模块或问题，不做范围外改动。它是存量重建的局部特例，除范围限定外，防堆叠约束同等适用。」

### 3.4 前置检查

比 ddd-rebuild 轻，须含两条。

1. 确认待重构范围可被明确描述，即用户指出具体模块或问题。
2. 确认版本控制系统在场，并记录回溯点。

### 3.5 流程

| 序 | 阶段 | 执行者 | 产出 | 门 |
|---|---|---|---|---|
| 1 | 问题界定与影响面圈定 | scout | 问题界定与受影响接缝 | 无 |
| 2 | 范围与锚点确认 | 根会话与用户 | 冻结范围与锚点 | 锚点冻结门 |
| 3 | 设计修订 | ddd-decomposer，涉及架构时加 ddd-architect | 设计文档修订 | 接口评审门，仅当接口变化时 |
| 4 | 实施 | ddd-implementer | 代码与测试 | 无 |
| 5 | 集成收口 | ddd-fixer | 集成收口结论 | 无 |
| 6 | 验证 | ddd-tester | 回归报告 | 无 |
| 7 | 审计 | ddd-auditor | 审计报告 | 审计门 |

### 3.6 锚点冻结门

同 ddd-rebuild 的人工门条款，位置为第 2 步。

### 3.7 防堆叠约束

须内联三条，这是定向重构与普通增量改造的关键区别。

1. 范围外文件不得改动，发现问题即登记为存量债务，不在本轮顺带处理。
2. 被重构范围内的产物整篇重写，不得在旧文本上追加。
3. 完成后须给出本次范围内的废弃项清单，即使为空也须显式声明为空。

### 3.8 产物

须列出三件并指向模板：冻结范围与锚点清单、范围废弃项清单、回归报告。

### 3.9 停止条件

与 ddd-rebuild 同构，范围相关项改为「用户未确认范围」。

## 4. 变更记录要求

两个 skill 为新增，须在 CHANGELOG 登记。其消费方为用户的显式调用，验证手段为加载与调用实测，满足声明面铁律。
