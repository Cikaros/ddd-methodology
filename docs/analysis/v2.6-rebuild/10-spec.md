# spec 改造契约

对象文件：`skill/ddd-methodology/references/spec.md`。本文件是本次改造的冻结契约。

## 1. 目标形态

新增一节，节序与标题固定如下，追加在末尾。

17. 存量重建
```

三级标题固定为。

```
17.1 适用条件与触发
17.2 前置检查与回溯点
17.3 价值锚点

## 2. 新增节内容契约

### 17.1 适用条件与触发

1. 开头给出可执行结论：「存量重建由用户显式触发，模型不得自动发起。」
2. 列出判定信号，至少三条：修补成本高于重建成本；结构健康度量持续恶化且恶化项的接受理由已穷尽；同构场景碎片累积到拆解不再能改善结构。
3. 明确一句：「触发时机由人工判断，落在入口。重建不由模型在常规迭代中提议并执行。」

### 17.2 前置检查与回溯点

本节为硬约束，须以编号步骤写出，固定表述如下。

1. 确认版本控制系统在场且可用。
2. 确认工作区无未提交改动，或已有明确的处置记录。
3. 记录回溯点标识，含提交哈希、分支名与记录时间，可按需附加标记。
4. 把回溯点标识写入重建产物并持久化。
5. 任一步骤不通过即停止，不得动工。

并须写明本节的语义：「丢弃是相对旧版本的丢弃，不是绝对丢失。旧版本始终可回溯，需要参照旧实现时从回溯点读取，不在案保留旧文件。」

### 17.3 价值锚点

1. 锚点限于三类，固定表述：对外契约；经审计确认仍然成立的设计决策；仍在被消费的能力。
2. 锚点清单由根会话产出，须经用户确认后冻结。
3. 冻结后不得扩范围。锚点之外一律可弃。
4. 未确认不得进入重建执行。

### 17.4 重建流程与门禁

以编号步骤写出，固定顺序如下。

1. 前置检查与回溯点记录。
2. 现状全量盘点与锚点候选提取。
3. 用户确认，冻结锚点与范围。此为一道人工作用门。
4. 按冻结锚点生成新架构与新设计，整篇重写而非修订旧文档。
5. 按新设计实施，实现与测试同等重建。
6. 集成收口，核对接缝并修集成问题。
7. 执行 AC 全量回归验证。
8. 派审计代理做声明面审计。
9. 通过后执行旧产物废弃清除。
10. 重写架构基线。

并须写明发散与收敛的分界：「第 2 步属发散段，产物为草稿，不入基线。第 3 步为冻结门。第 4 步起属收敛段，不得夹带范围外变更，第 2 步的草稿在冻结后作废。」

并须写明门名：「本节的门名为自载门名，不入全局门禁表，取值限定为五个：前置检查门、锚点冻结门、接口评审门、重建验收门、审计门，依次对应第 1、第 3、第 4、第 7、第 8 步。第 2、第 5、第 6、第 9、第 10 步无门。」

### 17.5 废弃声明与清除

1. 被替换的架构、代码、测试、文档与配置须逐项列入废弃清单，含原路径与替代物或替代位置。
2. 旧产物不在案保留。需要参照时从回溯点读取。
3. 清除在验证与审计通过后执行。
4. 未列入废弃清单而实际不再使用的产物，视为静默保留，属缺陷。

### 17.6 等价性验证

1. 重建属行为变更的特例。
2. 契约变更须逐项列入变更清单。
3. 行为等价性以 AC 全量回归验证，不得以子集用例证明等价。
4. 用例集合不得逆向缩减，缩减即堆叠信号。

### 17.7 与渐进式改造及定向重构的关系

1. 重建是一次性整体操作，不受「一次迭代只做一个级别」约束，该约束属渐进式改造节。
2. 定向重构是重建的局部特例，范围限定于用户指定的模块或问题，除范围限定外，本节条款同等适用。
3. 重建完成后，「触碰即治理」义务照常适用于后续迭代。

## 4. 不新增的内容

1. 不新增阶段键。状态文件节、阶段注册表与 workflow 的阶段集合保持现状，存量重建不走加速档。
2. 不改动门禁表的门号与门序。存量重建的门禁写在其自身节的流程步骤中，以四个自载门名承载，取值见 17.4。
3. 不改动脚本消费契约表。
