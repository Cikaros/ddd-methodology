# v2.5 机械强化设计

本轮是 v2.4 的延续。v2.4 把人工同步压缩为机械校验，残留两处仍靠人工维护：阶段键由 C4 双向校验维持，判定表默认分支由人工抽查。本轮把两处分别升级为单一来源生成与机械证据。

## 1. 目标一 阶段键单一来源

### 1.1 现状

阶段键共九项：`requirements`、`acceptance`、`architect`、`decomposer`、`interface-review`、`implement-plan`、`g5-int`、`test-execute`、`audit`。

存在三处副本。`workflows/ddd-workflow.js` 的 `stageRegistry` 数组是运行时定义。`spec` 状态文件节的键清单是规范定义。`extensions/ddd-governance.ts` 的 `G5_INT_STAGE` 是单键的守卫侧定义。

`ref-check` 的 C4 已双向校验前两处，但校验不生成，改一处仍须人工改另一处。

### 1.2 权威与方向

权威源为 `spec` 状态文件节的键清单。理由是方法论自述规范唯一权威源为 `references/spec.md`，把权威放在实现侧会与该自述冲突。方向固定为规范到实现，即 `spec` 为源，另两处为受控副本。

### 1.3 生成机制

`ref-check` 增加 `--fix` 模式。默认模式保持只读，`--fix` 才写盘。

`--fix` 的行为，按序如下。

1. 从 `spec` 状态文件节解析键清单，作为期望集合。
2. 重写 `workflows/ddd-workflow.js` 的 `stageRegistry` 数组块，使元素与期望集合逐项一致，顺序一致。
3. 校验 `extensions/ddd-governance.ts` 的 `G5_INT_STAGE` 值属于期望集合。不写该文件，因为该常量承载复核逻辑而非枚举，其值变更属语义变更，须人工处理。
4. 输出改动清单，退出码为 0。

`--fix` 完成后须复跑默认模式。若默认模式仍报漂移，说明存在 `--fix` 未覆盖的副本，属缺陷。

### 1.4 规范措辞调整

`spec` 状态文件节的键清单行去掉硬编码数量词，改为不含数字的表述，使 `--fix` 只需重写枚举子串。数量由枚举本身表达。

### 1.5 校验扩展

C4 由两方比对扩展为三方比对，即 `spec`、`workflow`、`extensions` 的单键。任一方缺失或多出即报漂移。

### 1.6 实现约束

键提取与比对改为单一实现，`ref-check` 的 C4 与 `--fix` 共用同一函数，避免两套解析漂移。

`--fix` 写盘前须先比对，无差异时不写盘并报告无需改动，保持幂等。

## 2. 目标二 判定表默认分支

### 2.1 识别判据

新增 C10 校验项。识别分三步。

1. 去围栏。按行扫描，处于代码围栏区间内的行不参与判定。模板骨架表在围栏内，须排除。
2. 分块。连续行且每行去除首尾空白后以竖线开头者构成一张表。不使用前后空行作为边界判据。
3. 判定。取表头行的列名，去除首尾空白与反引号后精确匹配。同时命中至少一个条件侧列与至少一个动作侧列者，判为判定表。

条件侧列名集合：`级别`、`条件`、`情境`、`触发点`、`判定条件`、`检查项`、`巡检项`、`声明面对象`、`产出物`。

动作侧列名集合：`处理`、`动作`、`处置`、`结论`、`追加加载`、`承接者`、`归类`、`不通过时的结论`、`不通过时的归类`。

列名匹配为精确相等，不得用子串包含。原因是 `机读结论` 与 `默认值` 等列名会造成误报。

### 2.2 默认分支判据

判定表须满足下列任一条件。

1. 表末行含下列任一词：`默认`、`其余`、`未命中`、`其他`、`无匹配`。
2. 表格结束后的三行内出现含上述任一词的句子。

判定矩阵这类由表后有序规则给出结论的表，额外允许：表格结束后的五行内出现 `判定顺序` 或 `结论取`。

### 2.3 需补齐的表

按上述判据，下列判定表缺默认分支，须在实施时补齐。

| 文件 | 表 | 补法 |
|---|---|---|
| `SKILL.md` | 条件加载判定表 | 表后补一句以「默认」开头的兜底句，即未命中任何条件时不追加加载 |
| `agents/ddd-doc-sync.md` | 巡检清单表 | 表后补一句以「默认」开头的兜底句，即巡检项均通过时结论为同步 |
| `agents/ddd-test-planner.md` | 情境与处置表 | 末行措辞改为含「其余」，或表后补兜底句 |

`spec` 派发表末行「无匹配产出物 | 根会话直接完成」已构成默认分支，纳入关键词集合后自动命中，无需改动。

### 2.4 验收标准调整

`00-overview.md` 与 `50-verify.md` 中 AC-3 的证据，由人工抽查第 3 项改为 C10 机械校验。

## 3. 实施分工

两个写入者，文件集互斥。

| 写入者 | 授权文件 |
|---|---|
| W1 | `scripts/ref-check.js` |
| W2 | `skill/ddd-methodology/references/spec.md`、`skill/ddd-methodology/SKILL.md`、`agents/ddd-doc-sync.md`、`agents/ddd-test-planner.md`、`extensions/ddd-governance.ts`、`README.md` |

W1 完成后方可执行 `--fix`，故 W2 先行完成规范措辞调整。两者文件集无交集，可并行，但 `--fix` 的执行须在两者均完成后。

## 4. 验证

| 项 | 命令 | 期望 |
|---|---|---|
| 校验全项 | `node scripts/ref-check.js .` | 十项通过，末行 `RESULT: pass` |
| 生成幂等 | `node scripts/ref-check.js . --fix` 后复跑默认模式 | 无改动且仍通过 |
| 生成可检出 | 在临时副本改动 `workflow` 的 `stageRegistry` 后跑 `--fix` | 副本回正，改动清单列出该文件 |
| C10 可检出 | 在临时副本删除某判定表的默认分支 | C10 报该表漂移 |
| 结构健康 | `node scripts/code-health.js .` | 无超限项，无相对恶化 |
| 门槛 | `node scripts/governance-check.js .` | `verdict: ok` |

`scripts/ref-check.js` 改造后行数须低于 500，接近 500 时按规范「粒度与独立性」节先拆解再交付。

## 5. 风险

| 风险 | 防护 |
|---|---|
| `--fix` 误改 `workflow` 源码结构 | 只重写 `stageRegistry` 数组块，写盘前先比对，无差异不写 |
| C10 误报数据表 | 列名精确匹配加条件侧与动作侧联立判据，已在 64 张表上验证零误报 |
| C10 漏报判定矩阵 | 以表后 `判定顺序` 或 `结论取` 线索豁免 |
| 脚本行数接近阈值 | 交付前度量，超限先拆解 |
| `--fix` 破坏只读定位 | 文件头声明改为默认只读且仅 `--fix` 写盘，写盘范围限于 `workflow` 的阶段注册表块 |
