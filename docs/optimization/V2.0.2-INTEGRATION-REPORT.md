# 2.0.2 全局联动重构与发布报告

> 范围：以 2.0.1 完整源码为基线，统一原有能力之间的连接点；不新增 DDD 业务命令、Agent 或 Skill，不改变「文档为唯一权威、代码为其落地」的项目目标。
>
> 状态：2.0.2 发布版。离线联动重构范围已完成并通过自查；真实 OpenCode SDK 与 DeepSeek Flash API 的端到端联调仍需在目标宿主环境独立完成（见 §5）。

## 1. 统一工作流

```text
/ddd-* 命令（15 个稳定入口）
    │ 统一命令注册表 / 子 Agent 权限映射
    ▼
命令派发 ──▶ 持久 Workflow 检查点 ──▶ 子 Agent 会话归属（持久）
    │                                  │
    ▼                                  ▼
宿主会话钩子 ──▶ 阶段与意图 ──▶ 最新项目证据 + 最新 Skills 匹配
                                         │
                                         ▼
                             角色工具许可 + 按需 Skill 读取
                                         │
                                         ▼
                          宿主工具事件 / 实际测试验收
                                         │
                                         ▼
                    统一 RPC overview ──▶ TUI 会话看板
                                         │
                                         ▼
                               G1–G6 / 持久看板
```

本版没有把模型宣称的「完成」视作测试验收，也不会在恢复会话时自动重放可能具有副作用的命令。

## 2. 已修复的跨模块脱节

| 原有问题 | 2.0.2 对应实现 | 验证关注点 |
| --- | --- | --- |
| 子 Agent 所属父会话仅在进程内存中，重启后可能丢失 | `src/lib/session-links.mjs` 持久化归属；`workflow-controller.ts`/`command-dispatcher.ts` 负责建立关联 | 重启恢复、冲突归属、符号链接拒绝 |
| 子 Agent 获得独立空上下文而丢失父阶段、任务和 Skill | `context-service.ts` 使用父会话状态与最新证据生成受限上下文 | 子会话继承和角色最小权限 |
| Skills 在提示词阶段匹配后被长期缓存，依赖变化仍复用旧结果 | `skill-plan.ts` 保留有限任务线索，每次上下文构建从当前项目重新识别 | 依赖更新、文件变更、任务提示匹配 |
| Agent 工具白名单不包含 `skill`，导致「推荐了技能却不能读取」 | `assets/role-tools.json` 为受约束角色添加 `skill`；只读评审仍禁用写操作 | 权限裁剪、Review 模式回退 |
| CLI、TUI 和 RPC 各自显示不一致的阶段/技能/门禁 | `session-overview.ts` 基于 workflow + board + gate + Skills 构建一个运行态视图，经 RPC/TUI 共享 | 实际状态变化后实时刷新 |
| 证据异常被静默吞掉，模型可能误以为读取成功 | `context-service.ts` 将读取失败转为显式异常摘要；损坏检查点在工具侧保守降级 | 损坏证据、检查点损坏 |
| 记忆关联指纹受阶段变化等非证据因素干扰 | `evidence-retrieval.mjs` 提供项目证据修订指纹；记忆对证据版本进行核验并兼容旧字段 | 证据变化、版本兼容 |
| Agent/Skill 分别物化，后续冲突造成已写入一半 | `materialize.mjs` 对 Agents、Commands、Skills 一次预检，冲突即在写入前退出 | 用户同名内容、重复安装、symlink |
| `/ddd-init` 先写项目文档，再发现技能冲突 | `scaffold.mjs` 先检查模板与完整物化计划，成功后执行初始化 | 冲突前无文档副作用 |
| 反漂移检查不覆盖工具授权、命令行为参数和跨文件版本 | `drift-check.mjs` 比对命令权威、Agent/Skill 权限和版本声明 | 版本漂移、权限丢失、命令字段不一致 |

## 3. 与 2.0.1 保持兼容

- 维持原有 **15** 个 `/ddd-*` 命令入口与参数命名。
- 维持原有 **12** 个 Agents 和 **33** 个 Skills；不要求用户为此次升级创建额外的常驻技能。
- 保持原有 G1–G6 门禁、DDD 设计树、测试树与变更流模型。
- 不覆盖 `.opencode/agents`、`.opencode/commands`、`.opencode/skills` 中用户自定义的不同内容；如需覆盖必须显式 `--force`。
- 新增 `materialize.mjs --check`：完整只读预检，不创建目录或修改文件。
- 会话归属信息记录于 `.ddd/state/sessions/`，不包含原始提示词或工具输出；继承父任务仅用于上下文及权限映射。

## 4. 离线验证方法

在包根（Node.js >=22.19.0，已安装依赖）执行：

```bash
npm ci
npm run skill-check
npm run check
npm run typecheck
npm test
npm pack --dry-run
```

另外可在临时项目中执行以下命令验证安装与幂等：

```bash
node --experimental-strip-types scripts/materialize.mjs all --root /tmp/ddd-smoke --check
node --experimental-strip-types scripts/materialize.mjs all --root /tmp/ddd-smoke
node --experimental-strip-types scripts/materialize.mjs all --root /tmp/ddd-smoke
```

`tests/integration202.test.mjs` 覆盖子 Agent 归属持久化、动态技能、上下文授权、统一状态、安装冲突、初始化预检、证据错误和运行时注册等连接链路。

所有测试结果、包完整性和独立解压验证应以实际执行记录为准，不能把使用离线 SDK 替身通过的类型检查解释为官方 SDK 的真实兼容性证明。

## 5. 已知外部验收边界

1. 官方 `@opencode/plugin@2.2.7` 类型下 `npm run typecheck` 未通过（`DEF-0018`）；须在真实 SDK 类型下修复后复验。
2. `tests/rc.test.mjs` 的跨进程锁符号链接用例在 Windows 上稳定失败（`DEF-0017`）；须修复文件锁的符号链接判定。
3. 未在真实 OpenCode GUI/TUI 宿主逐一运行 15 个命令与 RPC/TUI 面板。
4. 未执行 DeepSeek Flash 的真实 API A/B 任务，无法量化模型准确率、Token 缓存命中或响应时长提升。
5. 在本地源码工作区通过测试，不等于在用户最终安装路径和平台上自动通过；发布前应完成独立安装烟雾测试。

**结论**：2.0.2 的既定模块联动重构已完成并作为该版本发布；其**正式可用性**仍以目标宿主与模型端到端验证、以及上列 `DEF-0017`/`DEF-0018` 的修复复验为准。
