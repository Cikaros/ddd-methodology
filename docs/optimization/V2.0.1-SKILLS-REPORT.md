# ddd-methodology 2.0.1：Skills 重构完成报告

## 范围

仅实现此前确定的“必须完成”和“建议完成”：维持 DDD 方法论、15 个命令、12 个 Agents、原有 15 个 Skills 的 ID。新增 18 个独立技术 Skills：

- **必需语言（6）**：TypeScript、Go、Rust、C#、Kotlin、PHP。
- **建议框架（5）**：React、Next.js、Spring Boot、FastAPI、Flutter。
- **建议数据库（3）**：PostgreSQL、MongoDB、ClickHouse。
- **建议工具（4）**：Playwright、Vite、Kubernetes、GitHub Actions。

同时扩展既有 `dev-tools/references` 中包管理、构建、格式化、测试、数据库、CI/CD、可观测性、接口工具与消息队列参考，不再为每个工具新建常驻 Skill。

## 已改造机制

1. `assets/skills-catalog.json` 是唯一技能权威。运行时注册表、项目识别、物化器及 `assets/languages.json` 兼容投影均读它；后者由 `scripts/skills-sync.mjs` 生成，并由 `--check` 验证。
2. `src/lib/skill-router.ts` 对最多 500 个文件名/标记、少量受限配置清单进行检查；不读取业务源码和 `.env`，不遍历 `node_modules` 或符号链接。关键词、语言扩展名、项目清单、依赖命中形成可观察依据，按类与总量限制候选数量。
3. OpenCode 插件继续通过 `ctx.skill.transform` 注册。提示只保留约 5 个相关 Skill ID，完整 `SKILL.md` 交原生 `skill` 工具按需读取。未承诺宿主一定按模型提示成功调用 Skill。
4. `scripts/materialize.mjs skills/all --root <dir>` 将 package 中的 Skills 及 references 落为 `.opencode/skills/<id>`。默认冲突拒绝、全局预检、不覆盖用户自定义内容；显式 `--force` 才更新。
5. `lang-sql` 不再把 Redis 当作 SQL 方言。Vue/Android 的分类归于框架/平台，同时保留旧安装路径和 Skill ID。原先不可核验的假“2024修订号”改为可访问的上游参考 URL，并明确项目配置优先。

## 使用与迁移

```bash
npm ci
npm run skill-check
npm run check
npm run typecheck
npm test

# 现有项目先预览目标 .opencode/skills 冲突；无冲突再执行
node scripts/materialize.mjs skills --root /path/to/your/project
# 新项目初始化时，scaffold 会通过 materialize all 自动包含技能
```

从 2.0.0 迁移不需要删除现有 `.opencode/skills`。同名 Skill 若与随包内容不一致，物化器拒绝并给出路径；先人工对比，再决定是否显式覆盖，不能以 `--force` 当默认安装选项。

## 验证边界

离线测试能够验证目录完整性、选择逻辑、用户技能保护和旧命令注册，但不能在缺乏真实官方 SDK 和 DeepSeek API 的情况下证明实机 `skill` 调用、token 节省或准确率提升。本文只说明实现与可验证范围。
