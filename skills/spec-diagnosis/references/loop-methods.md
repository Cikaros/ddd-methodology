# 建回路方法细目

本文件是 spec-diagnosis 技能阶段一的方法细目，按贴近度与建成难度排列，前几种优先。目标都是同一个，即得到一条能对**当前这条**缺陷翻红的固定命令。

1. 失败测试。在最能触达缺陷的测试层（单元、集成、端到端）写下先失败的用例。
2. HTTP 脚本。对跑着的开发服务发请求，断言响应与已知正确快照的差异。
3. 命令行调用。以固定夹具输入调命令行，把标准输出与已确认正确的快照做差分。
4. 无头浏览器脚本。驱动界面并断言 DOM、控制台与网络。
5. 回放现场产物。把真实的请求、载荷或事件日志存盘，在隔离环境里重放同一路径。
6. 一次性脚手架。拉起系统最小子集，如单服务加打桩依赖，用一个函数调用走到缺陷代码路径。
7. 属性与模糊循环。缺陷是「偶尔算错」时，跑足量随机输入，找出失败模式。
8. 二分脚手架。缺陷出现在两个已知状态之间时，把「在状态 X 启动并检查」自动化，交给二分定位。
9. 差分循环。同一输入分别跑旧版与新版，或跑两套配置，比对输出差异。
10. 人在环脚本。最后手段。必须有人点击时，用脚本驱动这个人按固定步骤走，产物仍回流给定位者，回路保持有结构。

建成后把回路当产品来磨：更快，如缓存准备、跳过无关初始化、收窄测试面；信号更尖，如断言确切症状而非「没崩」；更稳，如钉死时间、固定随机种子、隔离文件系统与网络。一个半分钟的抖动回路不比没有回路好多少，两秒的确定回路才是定位的杠杆。

非确定性缺陷的目标不是干净复现，而是**提高复现率**：把触发跑上百遍、并行化、加压、收窄时序窗口、注入等待。复现率到一半即可定位，到百分之一则不可，故持续提高直到可定位为止。

## 脱敏

回路会展示命令、输出与现场产物，展示前先把每处秘密写成 `REDACTED`。凭据经环境变量进入回路，使秘密留在环境里而不落到展示的文本里；现场产物多带认证头，只引用承载信号的那几行。脱敏后不足以定位时，直接说明并索取，不得为凑可读性而复现秘密。
