# Go 模块

## 使用边界

此 Skill 是 **DDD 文档/验收流程中的技术参考**，不是新的门禁；项目明确的配置、框架版本和冻结设计优先。先检查仓库文件和锁文件，再选择命令。未验证的工具结果不得当成通过。若任务与本技术无关，不加载。

## 实施约束

1. error 逐层传播并保留上下文；不忽略返回值。
2. goroutine 必须有取消、超时和退出策略；共享状态用明确同步。
3. ctx 在 RPC/数据库调用中传递，使用 defer 及时释放资源。

## 常见反例

- nil interface 与 nil pointer 混淆
- goroutine 泄漏、竞态访问

## 可执行验证（先检测是否安装及配置）

- `go test ./...`
- `go vet ./...`
- `go test -race ./...（条件允许）`

不要在没有依赖、配置或授权时假定命令成功；失败时保存 stderr、退出码和关联源码版本供 G5/G6 核验。
