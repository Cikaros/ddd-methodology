# TypeScript 静态类型 · 操作参考

## 发现与选择

项目已有的 `README`、配置文件和锁文件优先于默认值。命令执行前先确认当前工作目录、目标环境及权限；输出仅作为验证证据，不自动替代 DDD 的设计/测试树。

## 实施检查

1. 严格类型与边界类型先行；优先 unknown + 类型缩小，禁止用 any 掩盖错误。
2. 接口/DTO 使用清晰的可导出类型，避免运行时与类型声明不一致。
3. 模块解析以项目 tsconfig 的 moduleResolution 为准，不擅自改成 CommonJS。

## 排错优先级

- tsconfig 与 ESM/CJS 不兼容
- 类型仅存在编译期，外部输入需运行时校验

1. 检查该项目使用的版本、包管理器和项目级脚本。
2. 最小化复现并记录退出码、关键错误和输入版本。
3. 改动对应的设计与测试，确认现象消失，必要时增加回归用例。
