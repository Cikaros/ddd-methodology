# 文档粒度与结构治理

判据要点在本正文，拆分形态与分工细节见 `references/document-rules.md`。

## 何时用

1. 产出或修订目录级与文件级设计文档，需要判断本文是否该拆时。
2. 判断同构场景是否达到拆解数量时。
3. 填写「对外接口与约定」节的契约表，需要确认契约数是否接近或超过上限时。
4. 产出测试计划、项目级指令文件与术语表，需要判断篇幅与结构时。

## 做什么

1. 文档粒度阈值：同构场景达到 3 个，或单一设计文档超 200 行或 10 项契约，必须拆解为分类文件或子场景子目录；父级只留共性契约与子场景索引，不重复子场景细节。
2. 接近上限的判定口径与代码类共用一处，定义在 governance-code，本技能只引用。
3. 契约数计数口径取设计文档「对外接口与约定」节的表格数据行数，表头与分隔行不计，该节无表格时取列表项数；口径的唯一权威在 `../ddd-methodology/references/spec-declare.md` 第十四节，本技能只引用。
4. 活文档与设计文档同受文档行数阈值管辖，含项目根的 AGENTS.md 与 GLOSSARY.md；术语表超过阈值时按领域拆分为分类文件，GLOSSARY.md 只留索引与拆解说明。
5. 文档树覆盖全部实现目录，模块级 AC 之和覆盖总 AC，无悬空接口引用，契约表列头完整。
6. 文档结构约定：每份文档首部含摘要，三行以内，每行指向后续节次或编号；章节名「模块级验收要点」与「用例清单」被机械校验锚定，不得改写；模板规定的机读行不得缺行，缺行或与正文矛盾即判缺口。
7. 产出文档的写入者同样负结构治理回执义务，回执字段与要求见 governance-code，本技能不重复其表体。

## 不做什么

1. 不重复产物骨架与字段填法，骨架见 `../ddd-methodology/references/templates.md` 与同目录各 `templates-*.md`。
2. 不定义代码粒度阈值与独立性判据，那属 governance-code。
3. 不定义文档内容的语义正确性判据，那属接口评审与交叉检查。
4. 不定义度量字段名与阈值数值的承载体，那属 `../ddd-methodology/references/spec-declare.md` 第十四节与 governance-code。

## 机械拦截面指针

| 约束 | 承载体 | 说明 |
|---|---|---|
| 文档行数与契约数超限、接近上限 | `code-health.js` 文档规模度量 | 仅报告不阻断 |
| 拆解判定 | 设计分解者 | 在分解设计期按本节的文档粒度阈值判定 |
| 锚定章节名与契约表列头 | 机械校验脚本 | 作缺口或告警输出 |
| 抽检 | 审计代理 | G6 核验文档规模恶化项 |
