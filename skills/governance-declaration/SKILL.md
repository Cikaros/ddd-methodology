# 声明面治理

判据要点在本正文，债务七件机制与未尽事项见 `references/declaration-rules.md`。

## 何时用

1. 判断一条声明是否应引入，即它有无消费方与验证手段时。
2. 做声明面审计，需要确定核对范围、反向抽查下限与探索性审计的判据时。
3. 判断某项声明该不该修剪，或核验上一轮修剪清单是否真的执行时。
4. 登记债务、判定超期与超上限、做教训回写时。
5. 需要给出审计报告归档名或核验归档命名时。

## 做什么

1. 铁律：不被消费的声明是危险的，因为无人验证其正确性。每条声明须同时具备消费方与验证手段，缺一不得引入。声明面含接口契约、公开导出、能力清单、规则条款、配置项、模板字段与依赖项。
2. 审计代理全量核对，不得因看似无用、低风险或成本高而跳过；对每项回答是否被消费与消费是否正确；发现无消费方声明即报缺陷，不得静默留存；反向抽查不少于三项，并实测消费路径真的通。
3. 探索性审计：除清单逐项核对与反向抽查外，须显式记录清单之外的检索面与结论。有发现时登记其归属，无发现时说明已检索的范围与手段，使无发现成为可复核的结论而非缺省；不得以「清单全通过」代替本项记录，也不得为填满本项而虚构发现，本项不以发现数量为通过条件。
4. 审计须同时核验变更记录当轮声称与实际产物是否相符，声称与实际不符即为缺陷，与代码缺陷同级处理。
5. 修剪：无用声明必须删除；声明面的修剪判据是无消费方，权限与动作归位见本节第 2、3 条。连续注释代码与兼容层标记的清理属 governance-comment，不在本条。
6. 归档与回验：审计报告在标题下方给出建议归档名，格式为 `G6-序号-版本`，序号取归档目录现存最大序号加一，被删归档不占序号，目录不存在时从 001 起；审计代理为只读，落盘由根会话执行；修剪清单在下次审计逐项回验，输入取该目录内上一份报告。
7. 运行时契约类声明，含 worktree、control 与 frontmatter 字段，以冒烟检查与运行时观察为验证手段，不因无法离线验证而判为纸面消费方。
8. 存量债务的登记与清偿：登记簿是唯一登记处，owner 必填且具名，禁止「留待下一轮」这类无对象的表述；未清项有总数上限，超限触发专项清偿轮，该轮不得新增功能；超期即阻断，连续两轮超期强制升级用户。字段、默认跨度与上限取值见 `../ddd-methodology/references/templates-debts.md`。
9. 教训回写：以新增或扩展机械校验清偿且根因为「机械校验有盲区」的债务，须把该根因转化为新的机械校验项并在校验覆盖登记中逐条登记映射，不得只改文档。

## 不做什么

1. 不定义粒度与结构判据，那些属 governance-code 与 governance-document。
2. 不定义注释与死代码的判据，那些属 governance-comment。
3. 不把审计代理的自陈当证据：机械证据由机械工具产出，判断型证据由指名代理逐条给结论。
4. 不承担声明的内容语义正确性判定之外的动作，即不代替缺陷修复与代码改动。

## 机械拦截面指针

| 约束 | 承载体 | 说明 |
|---|---|---|
| 债务超期、超上限与字段完整性 | `debt-check.js` | 末行结论为 pass 或 overdue，作交付门前置校验，由根会话经 `ddd_debt_check` 运行 |
| 无消费方声明占比 | `metrics-report.js` | 读最新一份审计报告的逐项审计表结论列 |
| 重复声明的语义判定 | 审计代理 | 机械侧只出弱信号，即同名声明跳文件出现 |
| 拒绝的契约写入与契约超限 | `governance-check` | 计入 G5-INT 的 verdict |
