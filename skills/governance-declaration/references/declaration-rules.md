# 声明面治理细则

本文件是 governance-declaration 技能的长条款补充，不重复技能正文的声明面判据。

## 一 债务机制的落点划分

| 机制 | 唯一载体 | 本文件补充的部分 |
|---|---|---|
| 统一登记簿与字段 | `../../ddd-methodology/references/templates-debts.md` 的骨架与字段说明 | 登记簿是唯一登记处，替代散落在变更记录句子、设计文档范围节与审计报告三处的登记 |
| 具名承接 | `../../ddd-methodology/references/templates-debts.md` 的 owner 字段 | 无对象的表述不算承接方，其验收判 rejected |
| 清偿时限 | `../../ddd-methodology/references/templates-debts.md` 的默认跨度字段 | 版本跨度按登记版本与应清版本计，与缺陷的修复轮次是两个量，不得混读 |
| 超期校验与升级 | 技能正文第 8 条 | 同一根因分类连续两版登记为未清，即判该根因未被真正处理，须在下一轮升级用户并登记为结构性问题 |
| 总量上限 | `../../ddd-methodology/references/templates-debts.md` 的上限字段 | 超限触发专项清偿轮，该轮不得新增功能；校验一律以字面值为准 |
| 历史快照与复发检测 | `../../ddd-methodology/references/templates-debts.md` 的快照段 | 复发段落只列出根因分类、牵涉条目与涉及版本，不改变末行结论与退出码语义；复发后的升级由根会话与审计代理承接 |
| 教训回写 | 校验覆盖登记文件 | 判据与反向完整性见下文第二节 |

## 二 教训回写的判据

触发条件为债务的根因分类是「机械校验有盲区」，且清偿方式为新增或扩展机械校验；执行者为根会话。登记逐条给出根因分类到已建立校验项的映射，并附所引来源债务编号；脚本类校验项以脚本文件名标识，仓库内校验项以校验编号标识。

三项机械判据，任一不成立即判漂移：

1. 映射中的每个校验项真实存在且被机械校验消费。
2. 条目的来源债务编号在登记簿中存在且状态为已清偿。
3. 条目的根因分类与该债务登记的根因分类一致。

反向完整性指以新增或扩展机械校验清偿且根因为「机械校验有盲区」的债务须在映射中有对应条目；该项无机械判据，由审计代理核验。不得为凑数登记不存在的虚项。

## 三 审计核对的组织形态

1. 全量核对的范围即声明面的七类对象，逐项给出是否被消费与消费是否正确的结论。
2. 反向抽查的实测对象取消费路径本身，不取声明的文本形态；专项审计可自行提高下限。
3. 探索性审计的记录与其归属登记合并为一节，避免清单结论与检索面结论两处分离。

## 四 债务与缺陷的分界

1. 债务不是缺陷。缺陷走缺陷四级路由的定级与轮回，债务是范围外或待补预判的项，登记后仍须按期清偿。
2. 两者共用两轮升级语义，以登记簿区分承接形态。
3. 改造影响评估的存量债务承接列是债务的入口来源之一，其承接方即登记簿的 owner。
4. 登记簿的时效由 `debt-check.js` 判定，其超期结论作交付门前置校验。
