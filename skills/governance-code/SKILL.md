# 代码结构治理

判据要点在本正文，长条款与细则见 `references/code-governance.md`。

## 何时用

1. 做粒度预判或实现落位，需要判断一个实现文件是否该拆、能否合并时。
2. 判断模块、类、函数、变量是否保持相对独立，实现是否引入隐式调用顺序时。
3. 触碰既有文件时，需要界定存量结构治理范围与拆解依据时。
4. 填写完成报告的结构治理回执时。

## 做什么

1. 按代码粒度阈值判定拆解：单文件超 500 行，基础或核心模块超 300 行，或一个文件承载 2 个及以上独立可测能力，三者命中任一即须拆解；接近上限指规模超过上限的零点八倍，此口径为本方法论内对代码文件与文档共用的唯一一处定义。
2. 被多模块依赖的基础能力独立成文件并配套独立单元测试；实现不得合并已拆解文件，不得创建未规划的超大单文件。
3. 保持独立性：函数优先无副作用，模块间只经冻结接口通信，类构造完成即可用，变量缩小作用域并优先不可变；契约未标注时序依赖即视为顺序无关，实现不得引入隐式顺序，独立单元测试以乱序调用验证。
4. 履行触碰即治理：写入者对所触碰文件的存量结构负治理义务，含连续注释代码与兼容层标记的清理，代码与文档同等适用，判据为本技能第 1 条的粒度阈值。
5. 文件已达或接近阈值时先按就近设计文档的粒度预判拆解；拆解不得超出预判，超出属设计偏离走 B 级；预判未涵盖且确实无法拆解时停止并报告，附预判未涵盖与已尝试的拆解方向两条依据。
6. 完成报告附结构治理回执，记被触碰文件的改动前后规模、是否拆解与依据的粒度预判；代码写入者记改动前后行数。本义务属 L1，不受渐进式改造的一轮一级约束。

## 不做什么

1. 不定义可机械判定的拦截面。硬拦阈值与守卫判定条件只在运行时守卫的实现里定义一处，本技能只给指针。
2. 不定义注释内容纪律与死代码清理的判据，那些属 governance-comment。
3. 不定义文档粒度与契约数阈值，那些属 governance-document；文档类只引用本技能第 1 条的接近上限口径。
4. 不承担存量重复声明的语义判定，那属审计代理。

## 机械拦截面指针

| 约束 | 承载体 | 说明 |
|---|---|---|
| 单文件阈值 | 运行时守卫 H-1 | write 与 edit 时按写入后行数估算，超限即拦截；文件内显式声明运行时例外者放行 |
| 基础或核心模块阈值、接近上限 | `code-health.js` | 仅报告不阻断，阻断地位由 G5-INT 的治理条件承接 |
| 实现文件粒度与设计预判一致 | G5-INT 的治理条件与签名一致性检查 | 判 drift 即阻断 |
