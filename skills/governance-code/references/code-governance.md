# 代码结构与粒度治理细则

本文件是 governance-code 技能的长条款补充。判据要点与阈值数字在技能正文 `SKILL.md`，本文件只补充正文未展开的运行期细节与剥离归属，不重复其判据。

## 一 运行时例外

受平台约束无法拆解的单文件可视为合规，须同时满足三项判定：

1. 平台受限：受平台约束无法拆解，如 pi workflow 沙箱脚本因无 `require` 与 `fs` 只能单文件。
2. 文件头显式声明：该约束已在该文件头声明，未声明不适用。
3. 单一能力域：文件内容控制在单一能力域内，超出时以任务文本分段而非文件拆分。

该例外按文件判定，不按目录或项目判定；适用者由守卫放行。

## 二 结构治理回执的字段

| 写入者类型 | 回执须记 |
|---|---|
| 代码写入者 | 被触碰文件的改动前后行数、是否拆解、依据的粒度预判 |
| 文档写入者 | 产出文档规模与文档粒度阈值的比对、是否拆解、依据的粒度预判 |

空节不得声明完成。回执属写入义务，不是事后审计，故在完成报告内给出，不等审计代理发现。

## 三 机械承载与豁免

阈值按档位分配承载体：

| 阈值对象 | 承载体 |
|---|---|
| 代码文件 | 运行时守卫硬拦，估算按写入后行数 |
| 基础或核心模块 | `code-health.js` 脚本度量 |
| 文档 | `code-health.js` 文档规模度量，配设计分解者的拆解判定与审计代理的抽检 |
| 文档契约数 | 同上 |

守卫豁免与默认：

1. 对非 DDD 项目静默，任何异常一律放行并记警告。
2. 未命中守卫各触发点的工具调用一律放行。
3. 新增写代码代理须在其 frontmatter 同步声明守卫扩展并登记，未登记者视为不受写入强制覆盖。

守卫的触发点编号与判定条件只在守卫实现里定义一处，本技能不复制其内容。

## 四 与相邻概念的分界

1. 粒度阈值管单件尺度；内敛次序律管整体是否发散，即文件数、规则并列数与设计文档份数是否随迭代增长。两者维度不同，互补而非重复。
2. 渐进式改造的分级衡量单次改动范围，与粒度判据是两类量，不得互相推定。
3. 注释与死代码的判据属 governance-comment；文档粒度与契约数阈值属 governance-document；本技能对文档只提供接近上限口径这一处定义。
