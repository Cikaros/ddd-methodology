# Markdown 写作约束

本技能只载模型不会下意识遵守的约束。可机械判定者落 `assets/markdownlint.json`，不在正文重复。

## 何时用

撰写或修订 Markdown 文档时，包括技能正文、设计文档、规范条款与项目文档。

## 做什么

- 标题用简洁名词短语。禁止在标题内使用括号补充或破折号补充，需要补充说明时另起短句。此条被仓库内的标题检查锚定，机械判据只能识别括号与破折号字符，识别不出语义上是否重复，故正文重申。
- 表格列数须一致，列头与分隔行的竖线数量必须相同。列数不匹配的表在渲染时静默错位，不报错。
- 链接文本须自解释，写明目标内容，不用「点击这里」「详见此处」一类无信息文本。
- 术语首次出现须给定义并附落地锚点。同一术语不得在多处另行定义，唯一权威处为该项目的术语表。
- 文档先给摘要再展开。核心文档在三行以内说清结论，细节置于其后。
- 标题层级按其所在文档的最大标题为基准逐级下降，不得以文档内出现过的绝对级别推断。子文档片段的标题级别须能被嵌入方正确接续。

## 不做什么

- 不写模型已熟知的通用格式常识，如空行、缩进、列表符号的一致性，这些由配置基线机械保证。
- 不重复 Markdown 语法说明。
- 不为美观调整表格列宽或对齐方式，行尾空格与多余空格由基线拦。
