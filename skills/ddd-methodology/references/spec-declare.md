本文件承载「结构与注释的机械证据」一节，另留「声明面可验证与修剪」节的指针；不包含门禁路由、变更与改造条款。

## 13. 声明面可验证与修剪

本节判据已移入治理类技能：声明面铁律、审计核对、探索性审计、变更记录核验、修剪、归档与回验、运行时契约类声明，以及存量债务的登记与清偿，归 governance-declaration 技能；连续注释代码与兼容层标记的清理义务归 governance-comment 技能。本节只留指针，不重复其定义。

## 14. 结构与注释的机械证据

`ddd_code_health` 工具（`root` 传被开发项目根的绝对路径）输出五类事实，作为 G5-INT 的证据源与 G6 审计的输入。度量写入 `<项目根>/docs/health.json`，**该文件入版本管理作为趋势证据，历史上限 50 条**，超出由脚本截断。输出含 `[告警]` 段，列出扫描面内不可读的目录与文件，无不可读条目时输出 `[告警] 无`；该段与末行结论同为固定行，输出超限截断明细时保留。

| 类别 | 覆盖的事实 | 机械程度 |
|---|---|---|
| 文件规模 | 超阈值的代码文件、基础或核心模块文件、活文档与设计文档、设计文档契约数，以及各类接近上限文件；阈值与判据见 governance-code 与 governance-document 技能 | 完全 |
| 死代码 | 连续注释代码块、兼容层标记、无引用文件 | 大致，不可达分支需 AST 故未覆盖 |
| 重复嫌疑 | 同名声明跳文件出现 | 弱信号，语义级重复需审计代理判定 |
| 注释 | 违禁模式与提及已不存在标识符的过时引用 | 部分，是否解释为什么不可机械判定，由审计代理抽检 |
| 结构趋势 | 被触碰文件的规模变化，超阈值文件数相对上轮的增减 | 完全 |

度量落盘的文档规模与契约数字段：`docFiles` 为纳入度量的文档份数，即活文档加设计树内设计文档，`docOversized` 为行数超文档阈值的文档数，`docNearLimit` 为行数接近文档阈值的文档数，`designFiles` 为纳入度量的设计文档份数，`contractOversized` 为契约数超上限的设计文档数，`contractNearLimit` 为契约数接近上限的设计文档数；文档规模与契约数超限、接近上限仅报告不阻断，其阈值与承载体见 governance-code 与 governance-document 技能。契约数的计数口径唯一权威在本节：取设计文档「对外接口与约定」节的表格数据行数，表头与分隔行不计，该节无表格时取列表项数；接近上限口径见 governance-code 技能，本节不重复展开。

活文档的度量范围：`skills`、`extensions`、`agents` 三个目录下的 Markdown 文件，加仓库根目录下除变更记录外的 Markdown 文件；变更记录即 `CHANGELOG.md` 不计入。原 `global` 目录已并入扩展，故范围改按新三目录计。该范围使随位置迁移的文档仍受同一阈值管辖，不因换位而脱离度量。

默认：上表未列出的结构事实不由 `code-health.js` 输出，须由审计代理语义判定；活文档规模已列入上表文件规模类，由 `code-health.js` 度量。

度量仅报告不阻断，其阻断地位由 G5-INT 的治理条件承接。度量恶化的具体项写入审计报告的必填节。

脚本消费契约表，消费方按本表解析各脚本的末行结论、退出码与门禁地位：

| 脚本 | 输出形态 | 机读结论 | 退出码 | 门禁地位 | 输出上限 |
|---|---|---|---|---|---|
| trace-check.js | 文本正文 | 末行 `RESULT: pass` 或 `RESULT: gap` | 0 通过，1 存在缺口 | G2、G4 与 G5 门禁 | 12000 字节 |
| span-check.js | 文本正文 | 末行 `RESULT: pass` 或 `RESULT: drift` | 0 无不一致（含不适用），1 存在不一致 | G5-INT 的接口签名一致性证据 | 12000 字节 |
| code-health.js | 文本正文 | 末行 `RESULT: report` | 恒 0 | 仅报告，不作门禁 | 12000 字节 |
| governance-check.js | 单 JSON | `verdict` 字段 | 0 通过，1 阻断 | G5-INT 门槛 | 12000 字节 |
| ref-check.js | 文本正文 | 末行 `RESULT: pass` 或 `RESULT: drift` | 0 通过，1 存在漂移 | 本仓库文档同步链 | 12000 字节 |
| debt-check.js | 文本正文；并写 `docs/debt-history.json` 债务快照 | 末行 `RESULT: pass` 或 `RESULT: overdue` | 0 通过，1 存在缺口（超期、超上限或字段不全） | 交付门前置校验 | 12000 字节 |
| metrics-report.js | 文本正文 | 末行 `RESULT: report` | 恒 0 | 仅报告，不作门禁 | 12000 字节 |

默认：未列入本表的脚本不构成任何门的证据。

trace-check 的判域在原有三层链路外补三层，末行结论与退出码语义不变。**R 编号机械追溯**：每条 R 须至少被一条 AC 承接，未被承接报覆盖缺口；每条 AC「对应需求」列引用的 R 须在 REQUIREMENTS.md 需求清单中真实存在，不存在者报悬空；编号形态由需求清单实得编号归纳，不预设前缀恒常与编号连续，识别不出编号体系或缺 REQUIREMENTS.md 时报「无法判定」并说明该断言未执行。**孤儿与悬空**：未声明需求编号或编号列为空的 AC 报孤儿；DESIGN「对外接口与约定」契约表出现的接口，复用签名级提取能力判定其在消费方模块所指代码文件中是否确有对应导出，无对应导出者报「无设计来源的接口」缺口，语言推导不出、消费方列填逻辑模块名或解析器未安装时报「无法判定」并说明，不得猜测；契约表消费方列的取值能对应项目根下目录或文件者通过，路径形态而不存在者报悬空，逻辑模块名而非路径者报「无法判定」，不得以模糊匹配猜测。**术语拼写一致性**：同一模块名在 DESIGN 消费方列、代码目录树与 TEST_PLAN 路径三面拼写一致，判定为去分隔符、转小写归一为同一键后逐字等值比较，键内原始拼写跨两个以上面出现两种以上拼写即报，不使用相似度阈值，只判拼写不判语义漂移。**义务核销**：读 `docs/board/` 下模块节点文件，断言抽取生成类义务条目均有对应节点、节点表合法（编号唯一、父节点可解析、确定度与状态取值合法、证据与理由齐备）、未闭合项已登记债务或承接方、已收口里程碑清零与相邻两轮快照冻结；项目已交付而看板仍在时报未清空缺口；`docs/board/` 不存在时报不适用。新增判据无可机械判定形态时一律报「无法判定」，作告警而非缺口，末行仍为 `RESULT: pass`。

span-check 的判域为签名级符合性：把 DESIGN「对外接口与约定」契约表的签名列与代码侧导出符号逐行比对，输出三态——一致、不一致、无法判定。**仅一致与不一致进机械门槛**：不一致计入缺口并置退出码 1，末行 `RESULT: drift`；无法判定只入报告不影响退出码，末行 `RESULT: pass`。**排除列**：契约表的「错误语义」与「时序依赖与副作用」两列不参与机械校验，因语法层只能部分推断 `throws`、`Result<T,E>`、`(T, error)`，不等价，不排除则判据本身不可满足。**解析器供给**：解析器按需从用户固定位置 `~/.pi/agent/ddd-parser/` 供给，其安装为仅用户触发的部署辅助，不进入被开发项目的流程；解析器缺失时报「无法判定：解析器未安装」并给出安装指引，属无法判定而非缺口。**语言推导**：语言由该行「消费方模块」列所指文件的扩展名推导，推导不出（列空、取值不唯一、填逻辑模块名或所指不是项目根下的文件）时报「无法判定」并说明，推导方式与语言白名单的单一权威见「接口先行与冻结」节，本节不重复展开。**位置权威**：解析器位置与锁定版本、语言白名单、契约表读取与比对各只有一份实现，分别为 `scripts/lib/span-parser.js`、规范「接口先行与冻结」节与 `scripts/lib/span-compare.js`，版本清单只在 `scripts/lib/span-parser.js` 一处。**不适用**：本仓库为方法论自身、或确无设计文档或契约行时报「不适用」并说明缺什么，退出码 0，绝不零对象报通过，判定口径见「本仓库适用边界」节。

DESIGN 契约表「消费方模块」列的填写口径与其后果，见 `templates.md` 的「对外接口与约定」段，本文不重复展开。

甲类脚本的调用默认由根会话经对应 `ddd_*` 工具，`root` 传被开发项目根的绝对路径，不再拼路径。收窄口径：G5 的机械证据须由根会话产出，因实现者不能自证；G5-INT 的机械证据由 `ddd-fixer` 产出，它本就独立于实现者，该代理可调用的甲类工具以其定义白名单为限，即 `ddd_code_health` 与 `ddd_governance_check`，G5-INT 的 `ddd_span_check` 证据仍由根会话产出。乙类与丙类脚本由维护者在本仓库内执行，调用边界见 `SKILL.md` 的机械门禁；输出上限按 UTF-8 字节计量，超限时截断明细，末行机读结论必须保留且完整。

`ddd_governance_check` 工具（`root` 传被开发项目根的绝对路径）输出单项 JSON verdict：每份 DESIGN.md 的接口节相对冻结锚点的 diff 与「变更记录」最新一轮声明的变更类型相符，`docs/health.json` 最新一条相对上一条问题类计数未上升，且存在设计文档树时其根路径已在 ARCHITECTURE 声明，三者同时成立时 verdict 为 `ok`，否则为 `blocked`；无设计文档树时接口冻结零考察，输出 `applicable:false` 与非适用说明，verdict 为 `ok`。问题类计数指超限类、死代码类与注释质量类，其键集合以该脚本内的单一常量为唯一权威，本节只作抽象描述而不另行罗列键名；接近上限类属预警阈值、未构成问题，弱信号重复类需语义判定，二者不参与阻断，只在脚本输出的报告中列出；`docs/health.json` 不存在时不判趋势。它作为 G5-INT 的门槛证据，退出码非零即 blocked；命令路径可确定时可经 typed gate 挂载。被开发项目须为 git 仓库，接口节 diff 对冻结锚点比对，非 git 项目退化为快照文件比对，本版不实现该退化路径，报无法判定而非缺口。传 `--freeze` 时把当前 commit 记为冻结锚点写入设计文档树根的冻结清单，供接口冻结节点使用，默认只读不落盘。
