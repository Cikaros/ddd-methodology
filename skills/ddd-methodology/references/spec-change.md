# 变更规范（spec-change）

## 三字段（对「执行过剩」的防线）

每行变更流必备：`rationale`（为什么做）／`outOfScope`（本次不做什么）／`expectedSignal`（怎么算做对）；另含 `id` / `ts` / `version` / `type` / `docs`。

## 版本与收尾纪律

- 版本号 `v<A>.<B>.<C>`；A 全局重构、B 新需求、C FIX 与其他；未明确要求时默认 +1。
- 版本落点**恰为三处**：`package.json` 的 `version`、变更流对应记录、使用者 `opencode.json(c)` 的钉版声明。
- **不得回写已发布版本组**：一经打 tag，其后变更落新版本组。
- 临时件产生即登记 `docs/temp.jsonl`；收尾按登记清理，完成后清空。

## 冻结即归并口径

- 变更流追加写、**唯一工具写入、禁止手改**（手改可机械检出）。
- 人读件 `docs/CHANGELOG.md` 由变更流**重放**得出，不手写。
- 归并**只删产物内联痕迹，不删权威变更流**。

> 行契约字段的机械校验由 `scripts/` 承担；版本号取值见术语表。
