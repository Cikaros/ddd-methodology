## 2. 质量门禁

流程按门的序列推进，未过门退回上一代理并记录于 `<项目根>/docs/gates/`；门号只是标识，序列才是唯一顺序依据。八门的判据、证据类型、执行者与不通过处置见 `SKILL.md` 第四节。

元规则，顺序固定：

1. 默认规则：本规范中可客观判定的条款均已挂门，门禁表即其归属索引。
2. 例外规则：仅下列条款未挂门，属指导性条款，不得作为验收依据。
3. 放行判据：放行与退回只以三类事实判定，即契约逐条被满足、边界与前置条件被遵守、异常路径被覆盖。可读性、表面完整度与「看起来正确」不构成放行依据；产出者自陈不是证据，审查者须核对契约表、用例表与脚本输出三类产物。本条归属 G4.5 与 G6。

未挂门清单：

1. 「问题与解法」节的三条解法陈述：属方法论定位表述，无独立可判定的违反形态。
2. 「并行实现与集成」节的并行前提段：三条前提只描述接缝划分的前置状态，其可判定部分已由 G3 与 G4 的退出条件承接，故该段本身不挂门。
3. 「二次开发」节：是否做现状分析取决于项目是否已有自身规范文档，属设计期判断，无门禁对象。
4. 「本仓库适用边界」节：范围声明，说明本仓库哪些门不适用，不构成对被开发项目的验收要求。
5. 「角色与交接」节的「执行模型」段：属定位性陈述，只描述固定编排与只读写二分，其可判定部分由派发判定与工具集二分承接，故该段本身不作门禁判据。

清单外若发现某条本应强制却未挂门的条款，处理方式是补挂门，而非降为建议；判断标准是该条款被违反时能否客观判定，能则必须挂门。

证据源只允许三类：机械工具或脚本命令，即可复现的机械证据，须写明工具名与参数或具体命令；指名代理，即判断型证据，须写明代理名与判据；运行时守卫，即由扩展在工具调用或收尾时机械判定并阻断，须写明扩展文件与判定编号。证据按类型分判断型与机械型两类：机械工具、脚本命令与运行时守卫为机械型，指名代理为判断型。G1、G2、G3 及 G6 的部分子项为判断型，门禁并非全门机械。

门禁记录由根会话写入 `<项目根>/docs/gates/G{门号}-记录.md`，记录须含机读行 `GATE: {"id":"G{门号}","round":<过门轮次>,"verdict":"<pass|fail>"}`：`round` 为过门轮次，首次过门为一、因退回而重过递增；`verdict` 取 `pass` 或 `fail`。该机读行是八道门一次通过率与过门轮次的来源，由度量聚合脚本读取该目录采集。记录另须逐项载明每类机械证据的运行方，即实际运行该工具或脚本的主体，不得只列工具名而略去运行者。过门时按 `templates-gates.md` 的门禁检查单填写，其检查项与证据类型同源，不得各写一遍。

甲类机械证据的规范产生形式为对应 `ddd_*` 工具调用，工具名、用途与产出方见 `SKILL.md` 第七节；脚本随包发布，不由目标项目提供。

**结构健康度量首版仅报告**，不作为阻断条件；G6 要求的是恶化项逐项给出接受理由或已定级改造，而非恶化项为零。G5-INT 的证据源中，`ddd_code_health` 恒退出零、仅报告不阻断，真正阻断者为 `ddd_governance_check` 的 verdict 与 `ddd_span_check` 的 drift。

## 3. 缺陷四级路由

四级表的级别定义、去向与是否经用户见 `SKILL.md` 第五节；定级自检按固定顺序执行，命中即停：

1. 自问该缺陷是否属 D 级，即计划是否遗漏场景、断言错或覆盖缺口。
2. D 级不成立时自问 C 级，即代码与就近设计何处不一致。
3. C 级不成立时自问 B 级，即实现者是做不出来而非没做对。
4. B 级不成立时自问 A 级，即是否需求本身矛盾或缺口。
5. 命中即停，取该级处理动作；未命中任一级特征时取最低适用级别。

只有 B 级及以上回设计层，A 级须经用户确认。同缺陷轮回修复超过两轮仍未解决强制升级用户，仲裁计入轮回；裁决记录写入缺陷路由单的裁决节，供下一轮排除。
