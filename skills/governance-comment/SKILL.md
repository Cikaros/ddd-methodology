# 注释与死代码治理

条款正文在本文件，延伸说明与未纳入清单见 `references/comment-rules.md`。

## 何时用

1. 新增或修改代码注释，需要判断该不该写、写到什么粒度时。
2. 修改代码后发现既有注释已与实现不符，需要判断修订范围时。
3. 触碰文件时发现连续注释代码、兼容层标记或冗余声明，需要判断是否属清理义务范围时。
4. 判断清理义务的触发时机时。

## 做什么

1. 注释只解释为什么，即意图、坑位依据与约束来源，不复述代码做了什么。密度基准为公共 API、复杂算法与已知坑位必须有注释，自解释的简单实现不加注释。
2. 禁止过度注释：逐行注释、显而易见的注释、大段叙述性注释，以及与代码重复的 docstring，皆为代码污染，不得出现。
3. 注释只描述当前代码，不牵连过程：禁修复史与对比叙述、轮次与编号、改动者与时间；读者只读当前代码与注释即可理解现状。
4. 文件级注释说明该文件的目标与范围，即存在目的、能力边界与不包含什么，随文件粒度拆解同步维护。
5. 修改代码时同步修订相关注释，过时注释必须删除，禁止留下与实现不符的注释。
6. 死代码与冗余声明必须删除，不得注释保留，不得以将来可能用到为由滞留；清理义务范围限于所触及文件内的连续注释代码与兼容层标记，即文件级属性。
7. 删除前确认无消费方并登记变更记录；无引用文件属仓库级属性，由审计代理处理，不入写入者义务。
8. 清理义务触发点六项：结构健康度量显示恶化时、G6 交付前、需求变更后、能力新增后、版本收尾、重建完成后。

## 不做什么

1. 不做仓库级无引用文件清查，那属审计代理。
2. 不定义声明面的消费方与验证手段判据，那属 governance-declaration。
3. 不定义文件粒度阈值与拆解判据，那属 governance-code。
4. 不以审查视角替代机械检查：可机械判定部分由 `code-health` 承担，本技能不复制其判据。

## 机械拦截面指针

| 约束 | 承载体 | 说明 |
|---|---|---|
| 死代码类与注释类 | `code-health` | 类别与覆盖事实见 ddd-methodology 技能的 `references/spec-declare.md` 第十四节；不可达分支需 AST 故未覆盖，是否解释为什么不可机械判定，由审计代理抽检 |
| 注释质量类计数参与门槛 | `governance-check` 的问题类计数 | 计入 G5-INT 的 verdict |
